# D81: ask_user_question and the session popup

Owner requests, 2026-11-14. Core: the tool `ask_user_question` (`tools/ask.rs`), deferred like every tool but `find_tools` (D30). Input `{questions: [{id, header?, question, options?: [{label, description?, recommended?}], multi_select?}]}`, 1 to 4 questions, 0 to 6 options; a label ending in "(Recommended)" (suffix dropped) or `recommended: true` marks the recommended option, moved first. Effect `Run` (it blocks on the user, so it never runs alongside other calls, D54) and exempt from the approval gate (D64).
- The wait reuses the session's `Gate` (`agent/approval/ask.rs`): `AgentEvent::QuestionRequest(QuestionRequest {id, call_id, questions, agent})`, then `QuestionDone {id, answer}` with `answered`, `skipped`, `cancelled` or `paused`; live only. `Session::set_asking(true)` marks a front end that answers, `Session::questions()`, `Session::reply(id, Option<Vec<QuestionAnswer>>)` (`None`: skipped). Stop, pause and close end the wait (`cancelled before it ran`, a paused text).
- Nobody answering (print mode, `serve`, the TUI for now): the tool runs and returns `no user is available to answer ...` at once (`ask::NO_USER`).
- Result: `The user answered:` then `- <id> (<question>): "<label>", ..., custom answer: "<text>"` per question.
- GUI: one popup (`ui/popup.slint`) at the bottom of the chat column, the composer's width, over the composer (hidden while it shows), for both approvals (`ui/approval.slint`, keys unchanged) and questions (`ui/ask.slint`, `src/ask.rs`): radio or check marks, the recommended option first with the lightning icon and the word "Recommended" (also in the accessible label), descriptions dim, always a last "Other…" row with a text box (typing chooses it), several questions stacked, scrolling past 60% of the window; Up/Down, Space, Tab, Enter submits, Esc skips. The chat keeps its frame (owner, 2026-11-14: never shrink it): the list keeps its full height and the composer's area its size (the composer is only hidden); while the popup shows Rust appends one trailing `MsgRow` of kind "spacer" (`src/spacer.rs`, from `App::refresh_run`), as tall as `TranscriptView.pad` = the popup's overlap with the list, so the last real row ends at the popup's top; opening the popup scrolls to the bottom (`to-bottom`), closing removes the row and a following view stays at the bottom; the user still scrolls the whole chat. The spacer is not a turn, step or navigator row: `mirror::Rows` for `VecModel` counts and writes above it (`spacer::count`, push inserts before it, replace keeps it).
- Focus: the popup owns the keys while it shows (`popup.grab()` on show and on a new question id; the composer gets the focus back on close). A question: Up/Down, Space, Tab, Enter, Esc in `AskPrompt`. An approval: the window's capture scope answers the keys.json approval chords first (D64), the popup scope maps Esc to Stop and swallows Enter and Space; Tab reaches only Decline.
- Tests: `popup_view_tests.rs` (software window: list height unchanged, spacer row last and the chat's end within 2px of the popup's top, removed on close, the wheel still scrolls; question keys give single, multi and Other answers as `ask::answers` builds them for `Session::reply`, Esc skips; approval Enter/Space/Tab never allow, Alt+Y answers, Esc stops; the mirror writes above the spacer). Shots: `shots_popup.rs` (`popup_shots`, approval and three questions over a long chat).
- Left: a TUI prompt; an end-to-end test from a popup click through `ask::connect` into a live `Session::reply` (the unit path is covered).
