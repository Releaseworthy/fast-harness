# D52: Native plugins and the build workflow

Owner, 2026-11-12: "ui plugin thì bắt buộc người dùng phải build lại hả (nếu phải build lại thì có thể tạo github action chuyên build cho người dùng tạo plugin được không)", gate G4 (docs/efficiency-plan.md phase 21C, `docs/plugins.md`). `fast_harness_core::ext`: `API_VERSION` 1, the API in `ext::v1` (`Ext::add_tool(Box<dyn Tool>)`, `add_provider(Arc<dyn Provider>, ProviderFile)`, `add_hook(Box<dyn Hook>)` with the seven D44 events, same input and `Answer`, run after the `hooks.json` entries and traced as `native:<name>`, `add_panel(Box<dyn Panel>)` answering with the D46 messages); a plugin exposes `pub fn register(ext: &mut ext::v1::Ext)` and calls `ext_api!(1)`: the major version is in the path, so a plugin for another major version does not compile (`compile_fail` doc tests). `ext::install` (once per process) and `ext::installed`, read by `Runtime::apply`: tools join every registry after the built-ins (deferred, D30), providers join the custom providers, panels the panel list (files win on the same id), `doctor` prints them. Crate `fast-harness-plugins` (only the binaries depend on it): `build.rs` parses `plugins.toml` (`[[plugin]]` `name`, `git` + `rev` or `path`; a TOML subset parsed by hand, no `toml` crate, D1) and generates `register_all` and `PLUGINS`; `bun scripts/apply-plugins.ts` writes the dependencies between marker lines of its `Cargo.toml` and the `[patch]` of the git core; `build.rs` fails when the two lists differ. An empty list generates an empty `register_all`; the host support costs `fast-harness.exe` +19,968 bytes (8,890,880 to 8,910,848) and `fast-harness-gui.exe` +19,456 bytes (31,363,584 to 31,383,040), release builds before and after on 2026-11-12. Workflows: `build-custom.yml` (reusable and by hand; inputs `ref`, `plugins`, `ui`, `targets`; gates, release build, artifacts, the caller's release on a tag), `ci.yml` (gates on push and pull request to main), `release.yml` (`v*` tags, empty list). Template: `templates/plugin-template/`. Unverified until the first run: MSVC for `ring` on `windows-latest`, the Linux packages for Slint, the build minutes.
