# D72 GUI background jobs: a pill and a popover with the job's output

Status: done; the pill moved to a tab after Trace in D76 (the popover is the same, under the tab) (2026-11-14).

## Decision

The GUI's chip strip of D68 is replaced by one small pill above the composer, shown only while the shown session lists a job: "N background jobs running" (N running) while one runs, else "N background jobs". A click (or Enter or Space on the focused pill) opens a popover anchored above it, as DeepSeek Harness does (`dsh-client-ui-jobs` `JobListAction`):

- A "Running" section and a collapsible "Finished N" section with Clear, which takes the finished rows off the list only (`jobs_view::Panel::cleared`, per session; the jobs stay in the session).
- Each row: chevron, state mark and word (never colour alone), the command, how long a finished job ran (`JobRow::took`, from the new `JobInfo::ended`), and Stop on a running row, which asks for a second click ("Stop?") and then kills on a thread as before.
- A click (or Up, Down and Enter) on a row shows its output below it: monospace, 180 px with its own scroll, at the end until the user scrolls, "Earlier output dropped" when the tail was cut.
- Escape or a click outside closes the popover (Slint `PopupWindow` with `close-on-click-outside`); closing hides the output and stops its reader. The popover closes by itself when no job is left.

## Output reading

`Jobs::peek` (core `tools/job_peek.rs`) returns the output still in the 64 KB ring without moving the read cursor of `Jobs::read`, so the model's `job_output` still gets every byte. `view::job_tail` cuts it to the newest 400 lines and 32 KB (the software renderer lays text out in i16 pixels). `TailWatch` is one worker for the expanded row only: it sleeps on the job's condition variable (`Jobs::wait_output_or_stop`, woken by `Jobs::wake` on drop), posts through `slint::invoke_from_event_loop` and waits 150 ms after each post, so a chatty job wakes the UI a few times a second at most. No timer on the UI thread and no read on it.

## State

`JobsUi` (global in `ui/job_row.slint`, exported from `main.slint`) replaces the `MainWindow` items `jobs` and `kill-job` (`docs/ui-contract.md`). A running row shows no duration: a live one would need a UI timer.

## Tests

Core `view/job_tail_tests.rs` (bounded tail, a peek leaves the model's read alone, the worker follows the job and ends when dropped), `view/jobs_tests.rs` (`took`); GUI `jobs_view_tests.rs` (row model, durations, Clear, software window: no pill without jobs, a pill click opens the popover, a row click asks for its output and keeps it open, Escape closes it and `closed()` fires once), `jobs_layout_tests.rs`, and the ignored `shots_jobs::jobs_shots` (no jobs, the pill, the open popover with output).
