# D85: The effort message stays where it was sent

Owner, 2026-11-15: a cache miss at the start of every user turn after a turn with thinking, and `request/transformations` dropping every earlier thinking block with `prefix_binding_mismatch` (1, 2, 3 ... per step).

Cause: on managed models (`Thinking::Managed`, Claude 5.x) `request::build` appended an effort-only `role: system` message (`output_config.effort`, beta `mid-conversation-output-config-2026-07-01`) at the end of every request and never kept it. Each thinking block is bound to everything sent before it, that message included; on the next request the message had moved behind the new assistant and tool messages, so every earlier block failed the prefix check and `drop_block` removed it. The per-message effort docs say to put the message after everything already sent and keep it in place; moving or removing it invalidates the thinking after it (<https://platform.claude.com/docs/en/build-with-claude/effort-per-message>, read 2026-11-15; <https://platform.claude.com/docs/en/build-with-claude/preserved-thinking/prefix-checks>, read 2026-11-15). Inside a turn the cache still hit (all thinking dropped the same way each step); at the next user turn the transformed history of the previous turn no longer matched its cached entries and the read fell back to the start of that turn (session 20261114-230458-3ce0: turn 2 start read 933 write 9090, turn 3 start read 10023 write 6913).

Decision: the effort message follows every user message with new input (`convert_messages`), at the same place on every later request, and only when the chosen effort differs from the top-level `high` (`Plan::turn_effort`); the cache breakpoint stays on the last user block before it. A change of effort mid-session changes the earlier effort messages once (thinking after them is dropped and the cache rewrites once); recording the effort per user message would avoid that and is not done. `tests/prefix_guard.rs` no longer exempts the effort message, and `request_prefix_tests.rs` checks that every request, within a turn and at the next turn, repeats the previous one message for message.
