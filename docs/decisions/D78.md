# D78: Skia on Direct3D 12 by default, the software renderer as the CPU choice

Date: 2026-11-14. Branch `gui-skia-d3d`.

## Owner requests

1. "Why OpenGL? For Windows native and the best performance it should be DirectX 12. And it must have subpixel rendering so text displays more nicely."
2. After the first version of this branch (2a1fa01: Skia, FemtoVG kept, subpixel text through a patched Slint crate), 2026-11-14: keep only the CPU renderer and DirectX 12 with grey text, DirectX 12 the default; remove OpenGL and the subpixel text.

## What Slint 1.18.1 offers (read in the crate sources)

- Skia on Windows renders through wgpu on **Direct3D 12**: `i-slint-renderer-skia` 1.18.1 enables `wgpu-30` by default, wgpu-30 is built with only `dx12` on Windows (Vulkan needs the `vulkan` feature), and `wgpu_30_surface/dx12.rs` 14 to 43 wraps the swap chain's `ID3D12Resource` as a Skia render target. There is no Direct3D 11 path.
- Present mode: `wgpu_30_surface.rs` 104 sets `wgpu::PresentMode::AutoVsync` (FIFO relaxed, else FIFO: vsync, no tearing).
- Order inside Skia (`lib.rs` 274 to 287): wgpu (D3D12), then OpenGL only where the cfg `skia_backend_opengl` holds (`build.rs`: the `opengl` feature, or neither Windows nor Apple nor wasm), then Skia's CPU raster surface (softbuffer). On Windows without the `opengl` feature no OpenGL surface is tried. Slint's winit backend (`i-slint-backend-winit` 1.18.1 `lib.rs` 161 to 199) tries Skia, then the other compiled renderers, then software, when no renderer is named; that fallback covers creating the renderer, not a later surface failure.
- `i-slint-renderer-skia` 1.18.1 depends on `glow`, `glutin` (`egl`, `wgl`) and `skia-safe` with `gl` without making them optional: they stay in `cargo tree` and `OPENGL32.dll` (the Windows system library) is loaded, but no OpenGL driver (`nvoglv64.dll`) loads. Removing them would need a fork of the crate.
- Text: no Slint renderer draws subpixel text (slint#5748). 2a1fa01 did it with a four-line patch of the Skia crate in `vendor/`; dropped by request 2.

## Decision

- `slint` features: `renderer-skia` and `renderer-software` (maintainer's OK for Skia, 2026-11-14); `renderer-femtovg` is gone, so FemtoVG, its OpenGL context and the `femtovg` crate are no longer built.
- `renderer` (user layer, `src/display.rs`): `auto` (default) leaves Slint's order: Skia on D3D12, else Skia on the CPU, then the software renderer if Skia cannot start. `skia` (aliases `d3d`, `directx`) forces Skia, `software` (alias `sw`) the software renderer; any other value, `femtovg` included, reads as `auto`. `SLINT_BACKEND` overrides it.
- Text is Slint's stock grayscale anti-aliasing on both renderers. `textAntialiasing`, `SLINT_SKIA_TEXT_AA`, `platform::lcd_text_order`, `vendor/i-slint-renderer-skia` and the `[patch.crates-io]` entry are removed.
- The prebuilt Skia library (skia-bindings 0.153.3) was built with a newer MSVC STL than the installed 14.42: without `platform/windows/stl_shims.rs` the stock crate still fails to link (`__std_search_1`, `__std_find_first_of_trivial_pos_1` unresolved, checked again after the patch was dropped). The shims define both with the STL's semantics; a toolset that has them links its own only when needed, ours win otherwise.
