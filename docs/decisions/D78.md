# D78: Skia on Direct3D 12 by default, subpixel text through a patched Slint crate

Date: 2026-11-14. Branch `gui-skia-d3d`.

## Owner request

"Why OpenGL? For Windows native and the best performance it should be DirectX 12. And it must have subpixel rendering so text displays more nicely."

## What Slint 1.18.1 offers (read in the crate sources)

- Skia on Windows renders through wgpu on **Direct3D 12**: `i-slint-renderer-skia` 1.18.1 enables `wgpu-30` by default, wgpu-30 is built with only `dx12` on Windows (Vulkan needs the `vulkan` feature), and `wgpu_30_surface/dx12.rs` 14 to 43 wraps the swap chain's `ID3D12Resource` as a Skia render target (`D3D12_RESOURCE_STATE_PRESENT`). There is no Direct3D 11 path.
- Present mode: `wgpu_30_surface.rs` 104 sets `wgpu::PresentMode::AutoVsync` (FIFO relaxed, else FIFO: vsync, no tearing).
- Order inside Skia (`lib.rs` 274 to 287, Windows build): wgpu (D3D12), then Skia's CPU raster surface (softbuffer). Slint's winit backend (`i-slint-backend-winit` 1.18.1 `lib.rs` 161 to 199) tries the Skia renderer, then FemtoVG, then software, when no renderer is named; that fallback covers creating the renderer, not a later surface failure, so a machine without D3D12 gets Skia on the CPU (no vsync), not FemtoVG.
- Text: no Slint renderer draws subpixel text (slint#5748). Skia can: the surface needs an LCD pixel geometry (`SkSurfaceProps`) and the font `Edging::SubpixelAntiAlias`. Slint passes no surface props (`dx12.rs` 41 and `software_surface.rs` 208: `None`) and leaves the edging at grayscale (`itemrenderer.rs` 1101).

## Decision

- `slint` gets the `renderer-skia` feature (maintainer's OK, 2026-11-14). `renderer` `auto` (default) leaves Slint's order: Skia (D3D12, else Skia on the CPU), then FemtoVG, then software. `skia` (alias `d3d`), `femtovg` and `software` force one (`src/display.rs`).
- `textAntialiasing` (user layer): `subpixel` or `grayscale`; unset follows Windows (`SPI_GETFONTSMOOTHINGTYPE` ClearType gives subpixel in the order of `SPI_GETFONTSMOOTHINGORIENTATION`, `platform::lcd_text_order`). `display.rs` passes it as `SLINT_SKIA_TEXT_AA` = `rgb`, `bgr` or `grayscale`; a preset variable wins. Only Skia reads it.
- `vendor/i-slint-renderer-skia` is the published 1.18.1 crate (`[patch.crates-io]`, `exclude = ["vendor"]` in the workspace) with these changes, each marked `Fast Harness patch (D78)`:
  1. `lcd.rs` (new): reads `SLINT_SKIA_TEXT_AA` once, gives `surface_props()` (RGBH or BGRH pixel geometry, else Unknown) and `edging()`.
  2. `lib.rs`: `mod lcd;`.
  3. `itemrenderer.rs` `draw_glyph_run`: `font.set_edging(crate::lcd::edging())`.
  4. `wgpu_30_surface/dx12.rs` `wrap_dx12_texture` and `software_surface.rs` `wrap_pixels`: `Some(&crate::lcd::surface_props())` instead of `None`.
- Updating Slint: copy the new `i-slint-renderer-skia-<version>` from `~/.cargo/registry/src/*/` over `vendor/i-slint-renderer-skia` (drop `.cargo_vcs_info.json`, `.cargo-ok`, `Cargo.lock`), re-add `lcd.rs`, re-apply the four marked lines, bump `slint` and run `cargo update -p i-slint-renderer-skia`. Drop the patch when Slint sets the pixel geometry itself (slint#5748).
- The prebuilt Skia library (skia-bindings 0.153.3) was built with a newer MSVC STL than the installed 14.42 and failed to link (`__std_search_1`, `__std_find_first_of_trivial_pos_1` unresolved). `platform/windows/stl_shims.rs` defines both with the STL's semantics; a toolset that has them links its own only when needed, ours win otherwise.

| this branch, software | software | 531 ms | 16 ms | 67 MB | 54 MB |

One run each: the CPU numbers are 1 to 5 scheduler ticks of 15.6 ms and vary between runs. Every run had a 1100x740 client at 192 DPI (scale 1.0). `fast-harness-gui.exe` grows from 33,025,024 to 42,955,264 bytes (+9.9 MB, the Skia library).

Subpixel text: `out/fh-render/crop-compare-gray-top-subpixel-bottom-x4.png` (PrintWindow, x4 nearest): coloured fringes on the subpixel crop; mean |R-B| over the crop 15.6 grayscale, 23.9 subpixel. This machine has ClearType off (`FontSmoothingType` 1), so `auto` drew grayscale here.

## Unverified

- No tearing under Skia D3D12 is inferred from `AutoVsync`; resize grabs (`out/fh-render/run-*/resize`) were not compared frame by frame and scrolling was not tried.
- The fallback to Skia on the CPU and to FemtoVG was not exercised (no machine without D3D12).
- Subpixel text in translucent layers, on a BGR panel and with ClearType on (the default path) was not seen; Skia's gamma does not follow the ClearType tuner (no `SK_FONT_HOST_USE_SYSTEM_SETTINGS` in the prebuilt binary).
