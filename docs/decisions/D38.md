# D38: Compaction

Owner, 2026-11-12, G2: "G2 50% windows đi và capped 500000 token (1 trong 2 cái này cái nào tới trước thì compact ở đó được không)": compact at 50% of the window or at 500,000 tokens, whichever comes first, overridable per provider and model (docs/efficiency-plan.md phase 13). `config.json` `compaction` `{auto: true, trigger: "50%", maxTokens: 500000, reserve: 16000, model: null, effort: "low", instructions: null}` (`trigger` a percent, `"150k"`, `"1.5m"` or a number) and `models` `{"<provider>/*" or "<model id>": {"compaction": {...}}}`; `config::compaction::resolve` layers defaults, `compaction`, every matching `<prefix>/*` (the provider id or the model id's prefix), then the exact model (phase 17A adds file layers there). Threshold = min(trigger, maxTokens, window - reserve - maxTokens of the request); an unknown window keeps only the token bounds: a 1M model compacts at 500,000, a 200K model at 100,000. When: at turn start and between steps (tool results complete), if `context` of the last step is above it; never between a call and its result; at most once until a step measured the new context, and once per turn after a failed attempt. How (every provider): one request with the frozen system, tools and messages plus the user message `agent::SUMMARY_REQUEST` (task, decisions, files with paths, current state, next action, durable facts; no tool call), no `tool_choice`, `compaction.model` and `effort` used for it, nothing streamed to the views; an answer that calls a tool is asked once more with each call answered by the error `agent::NO_TOOLS`. New history: `[summary of the session so far]` plus the summary; a synthetic `find_tools` call (id `compact_<turn>_<step>`) and result `Loaded: ...` naming the tools found so far (Claude gets `tool_reference` blocks, Antigravity the declarations); mid-turn `Continue the task.`. No old thinking; system and tools stay frozen; `Conversation::tool_session` read ranges are cleared. `after` is an estimate (4 bytes a token) until the next step. The `## Durable facts` section is also kept apart as `facts` (phase 20 writes it to memory). Overflow: a context-size error (Claude 400/413 "prompt is too long"; Antigravity 400 "exceeds the maximum number of tokens", "prompt is too long" or "input is too long", unverified live) or a `model_context_window_exceeded` stop compacts once and sends the step again; when the summary request does not fit either, the turn ends `context_overflow`. Manual: `/compact [instructions]` typed in the TUI or the GUI (a turn that only compacts, no `user/message`), `fast-harness compact [ID|latest]` (print mode, the summary on stdout). Tests: `tests/compaction.rs`. Later, measured first: Anthropic server compaction for models that list it.
