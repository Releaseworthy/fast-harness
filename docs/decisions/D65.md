# D65: Each session keeps its own draft

Owner decision 2026-11-13, his words: "each session keep its own draft, và khi ấn new session có draft text và switch về 1 session khác thì khi bấm lại nút new session thì vẫn còn draft cũ lại" (each session keeps its own draft, and when New session has draft text and you switch to another session, pressing New session again still shows the old draft).

## The bug

One composer served the whole window (GUI `ui/composer.slint` `text <=> area.text`) and one prompt line the whole terminal (TUI `tui/input.rs`), so text typed in one session went along into whatever session opened next, and the new session's text was lost when another session showed.

## The rule

- Every session keeps its unsent text. Switching from A to B saves A's draft and shows B's (empty when it has none); back to A shows A's again.
- The new session (not sent yet) has its own slot: type in a new session, switch to another session, press New session again, and the text is still there. The first prompt that creates the session moves the composer to the session's id, so the sent text never comes back in New session.
- A sent prompt leaves nothing behind: the composer owns the shown session's text and the store holds only the others, so the send empties it (the composer clears as before).
- Steers and queued follow-ups are unchanged: the composer clears on a taken send as before.

## Where

- **Core.** `app::drafts` (`fast-harness-core/src/app/drafts.rs`): `Draft { text, cursor }` (a UTF-8 byte offset) and `Drafts`, keyed by `Option<String>` (`None` is the new session) plus the owner, the session the composer's text belongs to. `switch(current, to)` saves the composer's text for the owner (an empty text clears its slot) and hands back `to`'s draft, taken out of the store, or `None` when `to` already owns it (the composer keeps its text and cursor). `created(id)` moves a new-session owner to its id.
- **GUI.** `src/drafts.rs` with `App::drafts`. `MainWindow.draft` (`<=> composer.text`) reads the text and `show-draft(text, cursor)` sets it. `TextArea` moved from `ui/widgets.slint` (at the 500-line limit) to `ui/textarea.slint`, with `set-cursor` (Slint `set-selection-offsets`). Slint does not expose the cursor of a `TextInput` (`cursor-position-byte-offset` is internal), so a draft shows again with the cursor at its end.
- **TUI.** `Tui::drafts` and `Tui::fresh` in `tui/app.rs`, the switches in `tui/open.rs`, `Input::take_draft` and `show_draft` in `tui/input.rs`. The cursor is kept. The TUI creates a log for a new session at once (an empty one), so "new session" there is `fresh`: the session the TUI started with an empty log, or the one New session created, until its first prompt.

## The open on a worker (D60)

The composer moves at the ask, not at the arrival: the moment a session is asked for, its draft shows (it is in memory, no parse), so while "Loading the session…" shows the composer never holds the previous session's text. Text typed while a session loads is that session's. A newer ask moves the composer again, so a superseded open never swaps a draft when its result is dropped. An open that fails, cannot start or that the service refuses moves the composer back to the shown session's draft. Choosing the shown session while another loads cancels the open and moves back too.

## Storage

In memory only, for the life of the window or the terminal: no file, no format change. No existing persisted place fits (the session log is append-only history, the index is a cache of summaries, D60).

## Tests

`app/drafts_tests.rs` (7), GUI `src/drafts_tests.rs` (4: A to B to A, the new session's draft, a sent draft, a dropped or failed open) and TUI `tui/drafts_tests.rs` (the same 4, the first with the cursor). The GUI and TUI tests failed before the change on the draft assertions; the core tests came with the new type.

## Known limits

- One new-session slot per window, shared by the workspaces of the GUI (a workspace switch opens a new session and shows that slot).
- The TUI takes the prompt out at Enter even when the send is refused while a session loads (D60 behaviour, unchanged).
- A UI folder exported before D65 (`fast-harness-gui-live`, D51) lacks `textarea.slint`, `draft` and `show-draft`; how the live preview handles the missing names was not tried (unverified): export it again.
