# D45: Keys

Owner, 2026-11-12: "tao muốn mọi thứ đều custom và chỉnh sửa được" (docs/efficiency-plan.md phase 17B part 2, `docs/extending.md` lists every action and default key). `fast_harness_core::keys` (no UI types): `Key` (`ctrl+alt+shift+meta+<name>`, parse and format, `label` for hints), `TUI_ACTIONS` (33) and `GUI_ACTIONS` (13), each with a scope, a state (`always`, `idle`, `running`; a state action wins over an `always` one on the same key) and default keys; `Keymap` (lookup, conflicts: same key, overlapping scope, same state). `keys.json` `{"version":1,"tui":{"<action>":"<key>"|["<key>",...]|null},"gui":{...}}` in the user folder and a trusted project folder (`keys::load`, read in `load_settings`, kept in `Runtime::keys`): later layer wins per action, `null` unbinds; an unknown action or section, a bad key and conflicts go to `Keys::problems` (doctor `keys:` section and a one-time note), a non-JSON file or another version is skipped. TUI: `tui/keys.rs` maps crossterm events to `Key`, `Ui::keys` dispatches the global, chat and screen actions, the hint line is built from the bound keys. GUI: a window `FocusScope` `capture-key-pressed` and the composer `key-pressed` call `key-action(scope, text, ctrl, alt, shift, meta, busy)`, Rust (`src/keys.rs`) answers the action name and `run-action` in `main.slint` runs it; window actions need Ctrl, Alt, Meta or a function key; text editing stays native. `fast-harness keys [--json]` prints the effective map with the source of every action; GUI Settings > Configuration lists `keys.<front>.<action>` rows.
