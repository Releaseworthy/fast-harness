# D55: Shared files: store module and locks

Owner, 2026-11-12 (docs/architecture-plan.md gate G6, "One store module with a lock"). Every file under the home folder is written by `store::write_atomic` (unique temp name per process and call, `sync_all`, rename). A read-change-write goes through `store::update`: it holds `<file>.lock` (made with `create_new`, `{"pid","started"}`; stale when its process is gone, or unreadable and older than 10 s; without a liveness backend after 10 min) and re-reads inside it. `workspaces.json` merges this process's changes. A session `<id>.lock` is made with `create_new`: a lost take refuses the turn. No format changes.
