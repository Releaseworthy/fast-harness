# D66: Cancel of a silent stream

Owner, 2026-11-13: phase 31 item "cancel of a silent stream" (docs/architecture-plan.md finding D5). Before this, a cancel (Stop, Esc, Ctrl+C, `session/cancel`) was seen only when a chunk arrived; `net` waits up to 600 s per read (`DEFAULT_READ_TIMEOUT_MS`), so before the first byte, in a silent thinking pause, or on a provider that sends no pings, Stop did nothing for up to 10 minutes.

## Decision

- **Contract.** `HttpRequest` gains `cancel: Option<&AtomicBool>` (`with_cancel`, `cancelled()`), and `HttpErrorKind` gains `Cancelled`. Both are `#[non_exhaustive]` (D57), so a plugin that builds requests with `HttpRequest::new` and matches kinds with a wildcard still builds. A transport that ignores the flag is cancelled only between chunks, as before. `http::CANCEL_BOUND_MS` (500) is the bound the tests hold both transports to.
- **Users.** The Anthropic and `openai-chat` providers pass `ChatRequest::cancel`; MCP over HTTP passes its call's flag (a cancel answers `cancelled`, as a cancel between chunks did). OAuth requests carry no flag (nothing cancels them). The providers already turned any transport error under a set flag into `ErrorKind::Aborted`, which the turn ends as `Cancelled` (`agent/call.rs` `on_error`): no change there.
- **`UreqTransport`.** A request with a flag runs on its own thread (`net::call`, named `fast-harness-http`, one per call: the "one helper thread per call at most" of the plan); the calling thread hands over the chunks and rechecks the flag every `net::POLL_MS` (50 ms since the review of 2026-11-13: 20 wakeups a second during a silent wait instead of 100; process CPU over 8 s of silent wait read 0 to 15.6 ms at both settings, the Windows tick, so the wakeup count is the measure; real socket cancel 9 to 46 ms, ignored test `measure_a_long_silent_wait`). The two threads go in lockstep (each chunk waits for the caller's `Flow`), so `Flow::Stop` ends the read exactly as before and a finished response returns its connection to the pool (test `calls_with_a_cancel_flag_reuse_one_pooled_connection`). On cancel the caller returns `Cancelled` at once and shuts the call's sockets down. A request without a flag runs on the calling thread as before.
- **Shutting a socket down.** ureq 3.5.1 lets a connector register a `ShutdownHandle` per socket (`ConnectionDetails::register_shutdown`, read in the crate source `src/unversioned/transport/mod.rs` and `tcp.rs`; `TcpStream`'s handle calls `shutdown(Both)`, which makes a blocked read return). `Agent::shutdown` would end every call of the shared agent, so `net::watch::WatchedConnector` wraps ureq's `DefaultConnector` (same chain, built with `Agent::with_parts` and `DefaultResolver`), keeps each connection's handles in its transport (`Watched`), and `Watched` hands them to the call using it before every wait through a thread local of the call thread (pooled connections move between calls). A socket registered after the stop is shut down at once and the connect fails.
- **Model list.** `GET /v1/models` has no cancel trigger in either front end, and the pickers start no second fetch while one runs, so its connect and each wait now end after `llm::anthropic::wire::GET_TIMEOUT_MS` (20 s) instead of 600 s.
- **Silence limit kept.** The 600 s per-read limit still ends a silence nobody cancels.
- **No async runtime, no new crate.**

## Trace

A cancel in silence writes the same records as a cancel between chunks: no `assistant/message`, `turn/end` with `cancelled` (tests compare the record kinds of both).

## Tests (failing before the change)

- `tests/silent_cancel.rs` over `ScriptedTransport::with_silence(call, chunks)` (silent until the flag is set, else `SCRIPTED_SILENCE_MS` then `Timeout`): an Anthropic turn silent before the first byte and silent after a text delta, each ends `Cancelled` within the bound with the trace of a cancel between chunks; `openai-chat` silent at 0 and 1 chunks ends `Aborted` within the bound. Before: 9.85 s each (the scripted limit).
- `tests/net_cancel.rs`, local `TcpListener` only: waiting for the head (a server that accepts and never answers), a silent body after `abc`, connecting (a closed local port, which Windows retries for about 2 s before refusing), a call without cancel, pooled reuse. Each cancelled call returns within the bound, the server sees the socket closed, and `net::live_calls()` returns to 0. Before: 4.7 to 4.8 s (the test's 5 s limit) and the connect state 2.04 s.

## Measured (debug build, Windows, 2026-11-13)

Cancel to return: real socket waiting for the head 9.1 ms, silent body 3.8 ms, connecting 5.1 ms; scripted turn before the first byte 3.9 ms, mid-stream 2.8 ms; `openai-chat` 2.5 ms and 3.5 ms.

## Limits

- Connecting and name resolution cannot be interrupted with std sockets: the caller returns at once, but the call thread lives until the OS ends the connect (1.92 s in the closed-port test; at most the 30 s connect limit) or the resolve, and then closes its socket. Only one such thread exists per cancelled call.
- A Stop click in the real window was not tried for this change.
