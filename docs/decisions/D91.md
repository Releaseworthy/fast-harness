# D91: shell hints and search notes say only what is true (2026-11-15)

The owner's retest of D89 in a real session found five wrong or missing notes.

- A recursive listing is judged per listed path in that path's own repository (nearest `.git`), so `cd <repo>; gci -Recurse node_modules`, `-Path <abs>`, `% FullName` and `Select FullName` from another working folder get the glob hint. When the working folder is not in front of the paths, the folder all listed absolute paths share (two names deep at least) is left out once, with the same note.
- The read hint fires only for a plain read (`shell_read.rs`): `Get-Content`/`gc`/`cat`/`type` as a whole statement whose output goes straight out, at most through `Select-Object -First/-Last/-Skip/-SkipLast/-Index` or `Out-Host`. A pipe into anything else, an assignment or an expression is data processing.
- A hint says `find_tools loads it` only for a tool not in `ToolCtx::loaded` (empty means every tool is loaded).
- Binary size: the shell reads the pipe as bytes, but `Get-Content` without `-AsByteStream` already decoded and re-encoded the file, so the true size is not recoverable from the stream. A decoded stream says `[binary output, about N bytes]`; a plain read of one existing file says `[binary output of <name>, <size> bytes]` with the file's real size (`cd` with a literal path or `$env:NAME` is followed).
- grep names the limit that cut the list: `the N-byte output budget holds M` when bytes ran out, `max_results A capped to M` only when M were shown.
- grep and glob count a left-out entry only when the glob could match it: inside or on the way to the glob's literal folder (`src/m1/**` → `src/m1`), a file when it matches, a hidden folder when it holds a matching file. `.git` never counts. The owner's 2 vs 1 was `.gitignore` (hidden, counted by grep `.`, not matchable by glob `node_modules/**`), not `.git`.
