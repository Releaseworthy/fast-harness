# D88 Session file state survives a reopen; main-session cache TTL by step

- File state: `<id>.files.json` beside `<id>.out` (version 1, `{"version":1,"files":[{path,hash,call}]}`) is written through `store::write_atomic` on every read/edit/write record and loaded by `ToolSession::new`, so `-c` and a reopened GUI session (both `Conversation::reopen`) keep what was read and written. Line hashes are not kept (the first read after a reopen returns the file whole). A file changed on disk since has another hash and is still refused. The hash is `DefaultHasher` (fixed keys): a toolchain change only makes edit ask for a read again.
- Cache TTL: with `cacheTtl: auto` in the TUI/GUI (`interactive`), tools and system stay 1h, a turn's first step (trailing user message) marks its tail 1h, a tool-loop step 5m, and the latest user message before the trailing one keeps a 1h breakpoint (reads after a pause even past the 20-block lookback). Order stays 1h before 5m. A 5th breakpoint drops the OAuth identity block's, then the last tool's (`llm/anthropic/cache.rs`). Explicit `cacheTtl: "1h"` keeps every breakpoint 1h, `"5m"` every one 5m; subagents unchanged (system 1h, messages 5m).
- The step that ends a turn is not known before its response, so "1h for the last step" is approximated by 1h at the next turn start: after an idle over 5 minutes the previous turn's loop is written again at 1h.
