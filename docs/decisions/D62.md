# D62: An untrusted project supplies nothing

Owner decision, 2026-11-13: `docs/architecture-plan.md` gate G12, option b. Advice taken: one rule, "an untrusted project supplies nothing".

## The rule
The `AGENTS.md` files of a project follow the same trust rule as `<project>/.fast-harness/` (D41): nothing loads until the user trusts the project once (`/trust`, `fast-harness trust`). Untrusted, the root to working folder files stay out of the system prompt and nested files (D43) are never attached to a tool result.

## What "the project" is
`config::layers::trust_root(home, dir)`: the nearest folder at or above `dir` with a `.fast-harness` folder (the D41 project), else the repository root (the nearest folder with `.git`), else `dir` itself. `/trust` trusts this folder. The `AGENTS.md` of folder `dir` loads when `trust_root(home, dir)` is in `trusted.json` (`layers::agents_trusted`). So a file between the repository root and a `.fast-harness` project below it belongs to the repository root's own answer: it loads only when that folder is trusted, and the note names it otherwise.

The home folder's own files (`system-prompt.md`, `prompts/<slug>.md`, memory) are not project files and still load.

## The note
The untrusted note (`Layers::untrusted_note`, shown once per load) names the project, says the `.fast-harness` folder was not loaded when there is one, and lists the paths (never the text) of the `AGENTS.md` files left out: `project <root> is not trusted: ... its AGENTS.md files were left out of the system prompt (<paths>); type /trust or run `fast-harness trust` to load it (AGENTS.md joins the system prompt of the next session; a running session gets it as a context update)`.

## A running session
The system prompt stays frozen (D36). After `/trust` the next turn of a running session reads the prompt sources again; the newly trusted files appear in the context stamp as added, so they reach the model once as a `[context update] <path> was added; it now reads:` note, never as a new system prompt. A new session has them in its system prompt.

## Replaces
D12's sentence that the `AGENTS.md` files of the session's project join the system prompt: they join it only for a trusted project. `Runtime::trust_project` now trusts `trust_root` (before: the project folder, else the working folder).
