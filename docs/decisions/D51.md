# D51: UI files

Owner, 2026-11-12: "ui plugin thì bắt buộc người dùng phải build lại hả" and gate G4 (docs/efficiency-plan.md phase 21B, `docs/ui-contract.md`). `fast-harness-gui --export-ui <dir>` writes the built-in `ui/*.slint` (`ui_files::FILES`, `include_str!`). `fast-harness-gui-live` (second `[[bin]]`, `required-features = ["ui-files"]`, root `src/live_main.rs`; both roots `include!` `src/root_items.rs`) uses Slint's live preview: `build/live.rs` sets `SLINT_LIVE_PREVIEW` for one extra `slint_build::compile_with_output_path` into `OUT_DIR/live_ui.rs` and replaces the build machine's main-file literal with `crate::live::main_file()`, so the typed `MainWindow` API stays and the rest of the crate is unchanged. The default root still uses `slint::include_modules!()` (ahead of time; the build script clears `SLINT_LIVE_PREVIEW` first). At start `live::prepare` stages `~/.fast-harness/ui` (with the binary's fonts and images) into `<temp>/fast-harness-ui/<pid>-live`, `live_check::check` compiles it with `slint_interpreter::Compiler` and checks `MainWindow` and every `docs/ui-contract.md` entry (name, kind, value type); a failure stages the built-in files and puts the error list (at most 12) in the banner. Reload (keys.json `reload_ui`, `f5`, or Settings > UI files, shown when `ui-files` is true) checks a scratch copy first and only then overwrites the watched folder (`main.slint` last); the live preview's watcher reloads it and re-applies every property and callback. Folders of dead processes are swept at start. The contract is generated by `ui_contract_scan` from the Rust accessor calls and the `.slint` declarations (`UPDATE_UI_CONTRACT=1` rewrites it). In `fast-harness-gui` the `reload-ui` callback only says which binary loads UI files.
