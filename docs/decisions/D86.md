# D86: Each user message keeps the effort it was sent with

Owner, 2026-11-15: with thinking on, the cache still broke at the start of a new user turn (`thinking_dropped`, `prefix_binding_mismatch`). The previous turns' thinking must go back the same way on every request.

Evidence: every `thinking_dropped` record in `~/.fast-harness/sessions` came from code before D85 (owner sessions 20261114-230458-3ce0 and 20261114-143322-54d8, A/B session 20261114-234904-2288, a 07:38 smoke run on a stale debug exe). After D85 no session had a transformation or a cache read drop at a turn start (owner 20261115-053943-38a0, opus high: turn 2 reads 15590 = the previous read 14650 + write 940). One rule still depended on the request instead of the message: the effort message after every earlier user message carried the effort of the current request (`convert_messages`, `thinking::managed`). Any change of effort (the picker, a `PreModelRequest` hook, `high` against another level) rewrote all of them: `messages[1]` went from `{"role":"system","content":[],"output_config":{"effort":"low"}}` to `"medium"`, every earlier thinking block failed the prefix check and the cache rewrote from the first user turn, a cost that grows with the turn count. The docs say to keep the effort message in place and never change it (<https://platform.claude.com/docs/en/build-with-claude/effort-per-message>, read 2026-11-15); a changed earlier message of any role fails the check, while `cache_control`, `effort` and other parameters do not count (<https://platform.claude.com/docs/en/build-with-claude/preserved-thinking/prefix-checks>, read 2026-11-15).

Decision: `Message.effort` records the effort a user message was first sent with (`agent/call.rs` `stamp_effort`, at the first call that carries it; a compaction summary call stamps nothing). `request::message_effort` repeats that level after the message on every later request; a message not sent yet takes the current effort. The stamp lives in memory only (`#[serde(skip)]`, not part of `PartialEq`), so the trace format is unchanged; a reopened session stamps its messages with the effort of its first call, as before. `tests/prefix_guard.rs` `prefix_guard_holds_when_the_effort_changes` runs three turns with thinking at low, medium and the default and checks that each request repeats the previous one message for message.
