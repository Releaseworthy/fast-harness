# D39: Steering, queue, pause, resume

Owner, 2026-11-12 (docs/efficiency-plan.md phase 14). `agent::Inbox` wraps an mpsc receiver (`Inbox::channel()` gives the front end its `Sender<agent::Input>`; `Inbox::empty()` has no input): `Input::Steer(text)`, `Input::FollowUp(text)`, `Input::Pause`. `Agent::run_turn_with(conv, text, cancel, &mut inbox, sink)` reads it without blocking at every step boundary (tool results complete): cancel, step limit, pause, compaction, then steers; `run_turn` is the same with an empty inbox. Steer: the texts that arrived (joined by a blank line) become one text block after that step's tool results in the same tool message (Claude: the same user message after the `tool_result` blocks, as https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls requires: "the `tool_result` blocks must come FIRST in the content array. Any text must come AFTER all tool results."; Antigravity: the same `user` content, after the `functionResponse` parts); running tools are not aborted; when the model ends the turn without tools and a steer came during that step, it is the next step's user text in the same turn. Traced as `user/message` with `kind: "steer"`; `AgentEvent::UserInput {text, steer: true}`. FollowUp: after a turn that ended `Done` (and no pause), a new turn starts with the late steers or else the oldest follow-up (`AgentEvent::UserInput {steer: false}`); `Inbox::leftover()` returns the texts no turn used. Pause: the step finishes its tools, the model is not called again, outcome `Paused` (`turn/end` `paused`); a steer that came with it is added first. `Agent::resume_turn(conv, cancel, &mut inbox, sink)` runs a turn without a user message on a history that ends with tool results or user text (`Conversation::can_resume`, after `repair`); else an `Error` event and `Failed` with nothing logged. A context update on resume is added like a steer (`kind: "context"`). `session::unfinished(events)` (also `SessionSummary::unfinished` and `Conversation::unfinished` on resume): `Interrupted` (a `turn/start` without `turn/end`: crash or kill), `Paused` or `Cancelled`, unless the history ends with the model's answer; a cancelled or crashed turn resumes on its repaired `interrupted` results. TUI: Enter while a turn runs steers, Alt+Enter queues (a newline when idle), Ctrl+G pauses, Ctrl+Backspace removes the last queued text; steers waiting and queued texts show above the input; queued follow-ups stay in the TUI and start when a turn ends `Done`; `/resume` continues a paused, cancelled or interrupted turn, and opening such a session says so. Print mode exits 1 on `Paused` (it has no inbox). GUI (`fast-harness-gui/src/runs.rs`, `turn.rs`): running turns are kept per session id (`Runs`: the shown `Run` drives the transcript rows, other sessions with a running turn or queued texts stay parked and their events, tagged with the session id, update only their own transcript), so several sessions run at once and opening another session or workspace no longer waits for a turn; Enter while the shown session runs steers, Alt+Enter queues a follow-up (a send when idle), Pause sits next to Stop; steers not yet read and queued texts show as chips above the composer (`ui/queue.slint`), a queued one removable with its x; queued follow-ups stay in the GUI and start after a turn that ended `Done`, also in a parked session; a paused, cancelled or interrupted shown session offers Resume (`Agent::resume_turn`); each sidebar session row carries a mark and a word: running, paused, interrupted or cancelled (`SideRow.run`). Tests: `tests/steering.rs`, `tui/steer_tests.rs`, `fast-harness-gui/src/runs_tests.rs`.
