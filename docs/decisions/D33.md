# D33: Themes as data, greyscale setting, vibrant set

Owner, 2026-11-12: "modern đẹp và màu sắc rực rỡ coi, thêm nhiều theme nữa", greyscale "là setting cho mọi theme á (có slider và ô nhập số) chứ không phải theme", "nên làm kiểu dễ mở rộng, về sau user họ cũng có thể tự tạo theme riêng của họ"; liquid glass asked, then dropped. Every theme is one JSON document in one documented format: `{"version":1,"id":"<id>","name":"<name>","kind":"dark"|"light","extends":"<theme id, optional>","colors":{"<role>":"#rrggbb"}}`; `extends` starts from another theme and changes only the roles listed (no cycles; a missing base is an error). Built-in themes ship in that format inside the binary; user themes live in `~/.fast-harness/themes/*.json` and are read at start and on Reload (a user file with a built-in id is skipped with a note). Built-ins: Dark and Light (redesigned), Aurora, Synthwave, Sunset, Emerald, Sakura (light), Citrus (light); the tests hold each to WCAG 2.2 and APCA Bronze. A user theme that fails the check still loads, and Settings lists its failing colour pairs with their ratios. Greyscale is one setting for every theme, `greyscale` 0 to 100 in `config.json` (`FAST_HARNESS_GREYSCALE`): each colour mixes in linear light toward the grey of the same relative luminance, so WCAG ratios stay the same at any value. GUI: Settings > Appearance, a slider and a number box kept in sync; TUI: keys step it. Greyscale dark and Greyscale light are removed: a saved one loads as Dark or Light with greyscale 100. Replaces the theme list of D15.
