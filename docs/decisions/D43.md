# D43: Skills and nested instructions

Owner, 2026-11-12: "tao muốn mọi thứ đều custom và chỉnh sửa được" (docs/efficiency-plan.md phase 19, `docs/extending.md`). `skills/<name>/SKILL.md` (Agent Skills: `name` else the folder, `description` needed and cut at 1024 characters) in the user and trusted project folders is a fourth index kind (`ExtIndex::skills`, names and descriptions only). A new session's frozen system prompt gets `Skills: a, b (load one with find_tools)` after the template (`Context::skills`, names up to 1 KB then "and n more"); a skill added later sends no context update (`find_tools` still matches it after a settings reload). `find_tools` (`tools::find::run_with`) matches skills by `names` and by `query` (best match scoring at least 2) and returns, after the tool lines, at most 3 blocks `[skill <name>: <folder>]` plus the body cut at 20 KB; with skills the find result skips the D37 budget; on Claude a result that loaded tools holds only `tool_reference` blocks, and the rest (unknown names, MCP matches, skill bodies) is a text block after the results of that message, opened by `[find_tools result, continued]`: references next to a text block are an HTTP 400, "Tool definitions/code execution functions cannot be mixed with other content" (live 2026-11-12, Haiku 5.5 on a subscription account). AGENTS.md from the repository root to cwd stays in the system prompt, capped by the new key `agentsBytes` (32768). A nested AGENTS.md below cwd (`agent::nested`) joins, at most 6 KB under `[nested AGENTS.md <path>]`, the first tool result whose `path` argument lies inside its folder, once per session, appended after the budget (outside it) and before the result is first sent or traced; the shell has no cwd argument. Loaded skills and nested files are rebuilt from the mark lines of non-assistant messages (resume needs nothing more); a compaction lists them under the summary (`compacted::KEPT`, event key `kept`), so they stay loaded. `doctor` and GUI Configuration list skills. The live `ToolResult` event shows the tool's own output; the log and the model get the appended text.
