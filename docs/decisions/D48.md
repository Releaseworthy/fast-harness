# D48: Sessions as a service (JSON and ACP)

Owner, 2026-11-12: "tao muốn mọi thứ đều custom và chỉnh sửa được" (docs/efficiency-plan.md phase 16 part 1, `docs/service.md`). `fast-harness -p --json`: a `session` line (`schema` 1), one object per `AgentEvent` with a snake_case `type` and camelCase keys (`service::json::event`), then a `result` line (`outcome`, ACP `stopReason`, `usage` of every turn, `durationMs`). `fast-harness serve --stdio [--model M] [--effort E]`: JSON-RPC 2.0, one JSON object per line, Agent Client Protocol v2 names (`initialize` with `protocolVersion: 2`, `session/new`, `session/resume` with `replayFrom: {"type":"start"}`, `session/list`, `session/prompt`, `session/cancel`, `session/close`, `session/set_config_option`, `session/update`) and ours `_fh/steer`, `_fh/follow_up`, `_fh/pause`, `_fh/continue`, `_fh/compact`, `_fh/stats`; stdout carries only protocol lines, notes go to stderr. Core `service`: `Service` (session table: id -> `Session` with the conversation, its own `Config`, the inbox `Sender<Input>`, the cancel flag, the turn thread) over a `Host` trait (`app::RuntimeHost` for the CLI, a scripted host in tests); `Service::start` runs each turn on its own thread, so sessions run at once and responses come in any order. `session/prompt` answers `{messageId}` once accepted (ACP); `_meta: {"fh/wait": true}` answers when the turn ends with `stopReason` and `_meta.fh/usage`. A prompt to a running session is a follow-up (D39), `_fh/steer` a steer. User message ids are `msg_u<history index>` (the same on replay). Settings per session: `session/set_config_option` takes `model`, `effort` (the advertised options) and any settings key (`maxSteps`, `compaction.percent`); stop reasons `end_turn`, `cancelled`, `error`, `max_turn_requests`, `max_tokens`, `_context_overflow`, `_paused`. Client MCP servers are refused (-32602; `mcp.json` holds them, D47).
