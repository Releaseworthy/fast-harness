# D63: PreModelRequest hook, hook budget, MCP session expiry

Owner decision, 2026-11-13, phase 29 of `docs/architecture-plan.md` ("a `PreModelRequest` hook, a total hook budget, MCP HTTP session expiry"; proof: a hook test rewrites one request). Findings E3, E6, E7.

## PreModelRequest
- When: once per step, before the step's first attempt, in main and subagent sessions (`agent/model_hook.rs`). Retries, account failovers and the call after an overflow compaction resend the same request and keep the step's change without running the hooks again. The summary request of a compaction does not run it (PreCompact covers compaction).
- Sees: `event`, `sessionId`, `cwd`, `turn`, `step`, `depth`, `model`, `effort`, `maxTokens`, `messages` and `tools` as `{count, bytes}`. Never the lease, the account, a header or a key (`hooks_model.rs` scans the hook's stdin for the scripted key). A native hook gets the same JSON value as a command hook: the `NativeHook` contract (D52) stays one input type for every event.
- May change, the smallest useful set: block the call (the turn ends `Failed` with `model request blocked by a hook: <reason>`); `effort`, one of `minimal`, `low`, `medium`, `high`, `xhigh`, `max`; a lower `maxTokens` (1 up to the request's own value); one context note, appended as `[hook context]` text to the newest user message, which the model has not seen, so request N+1 still repeats request N.
- Refused: `system`, `tools`, `messages`, `model`, `headers` and any other key under `request`, plus effort `off` and a raised `maxTokens`. The answer is then a `hook/error` with the reason, shown as an error note, and the request goes out unchanged (fail loud, never a silent cache loss). Why: the system prompt and tool list are frozen per session and messages are append-only (D36); Claude thinking blocks bind to the prefix and to `Message.model`, so a model switch would drop or invalidate them and the cache; `off` turns thinking off after thinking turns. Headers: `ChatRequest` has no header channel and adding one changes the `llm::Provider` contract for every provider, so none for now.
- Cost: an effort change keeps thinking on but on Claude a new thinking budget can invalidate the messages' cache (system and tools stay cached). It is the user's explicit choice and is traced.
- Trace: the existing `hook` and `hook/error` records with `event: "PreModelRequest"` and decision words `block`, `context`, `effort`, `maxTokens`; no new key, trace version unchanged.
- `ext::v1`: `HookEvent::PreModelRequest` (the enum is `#[non_exhaustive]`), `Answer::request` with `with_request`, `RequestChange` with `with_effort` and `with_max_tokens` (docs/plugins.md, Stability).

## Hook budget
- Besides each entry's `timeoutMs` (default 60 s), all hooks of one event occurrence share `budgetMs`, a top-level key of `hooks.json` (default `DEFAULT_BUDGET_MS` = 120000, two default timeouts; the smaller value when both the user and the project file set it). It lives in `hooks.json` because the other hook limits do; `config.json` holds none.
- A command hook starts with the smaller of its timeout and the time left; once the budget is spent the hooks not started are skipped: one `hook/error` per skipped hook (`skipped: the hook budget of N ms was spent`) and one note naming them all.
- Fail open: the turn goes on as if the skipped hooks had answered nothing, so a skipped `PreToolUse` block does not block (test `the_hook_budget_skips_the_rest_and_fails_open`). Why: D44 already fails open on a failed or timed-out hook, and a budget is the same kind of failure; hooks are user extensions, not the approval gate (a later chunk), and failing closed would let one slow hook end every turn.

## MCP HTTP session expiry
- Spec: MCP 2025-11-25, Streamable HTTP, Session Management (<https://modelcontextprotocol.io/specification/2025-11-25/basic/transports>, read 2026-11-13): a server that ended a session "MUST respond to requests containing that session ID with HTTP 404 Not Found"; a client that gets 404 to a request with `MCP-Session-Id` "MUST start a new session by sending a new InitializeRequest without a session ID attached". The current revision 2026-07-28 (<https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http>, read 2026-11-13) removed protocol sessions, so the rule applies to legacy-era servers only.
- Rule (`tools/mcp/http.rs`): a legacy request with a session answered 404 drops the session, sends `initialize` once and retries the request once. A failed re-initialise or a second 404 is the call's error and marks the connection dead: `alive` is false and the next call connects from the probe. No loop.

## `trust --cwd`
`fast-harness trust --cwd DIR` trusts DIR like `trust DIR` (every other subcommand reads `--cwd`); both at once is a usage error. The usage line says that trust also loads the project's `AGENTS.md` files (D62).
