# D40: Subagents v2

Owner, 2026-11-12 (docs/efficiency-plan.md phase 15; G1 "G1 theo plan": subagents get `tools`, the `tools.preload` setting comes in 17A). `subagent` arguments: `prompt`, `description`, `agent` (one hook, `subagent::agent_type`; no type exists before 17A, any name is an error), `model` (a picker id, `antigravity/<id>` too: `Runtime::router()` gives the provider and credential; without a router only a model of the parent's provider), `effort`, `tools`, `background`. (D80: `maxDepth` defaults to 1 since 2026-11-14, was 2.) Config `"subagent": {"model": null, "effort": null, "maxDepth": 1, "maxParallel": 4, "outputBytes": 8192}`; null inherits; `outputBytes` is the budget of `subagent` and `agent_output` results unless `toolOutput` names them. Nesting: the header has `depth`; a child below `maxDepth` gets the parent's tool list (built-ins, `subagent`, `agent_send`, `agent_stop`, `agent_output`, all deferred behind `find_tools`) and the parent's system prompt, so with the same model its `tools` and `system` equal the parent's (test `subagents.rs`) and its first request reads the parent's cached prefix; at `maxDepth` it has the built-ins only. Preloaded `tools`, the same on both providers: the tool array stays the parent's (no `defer_loading` change, which would move tools into Claude's cached prefix and break the sharing); the child's first turn starts with a synthetic `find_tools` call and result naming them (the pair compaction writes, D38), so Claude gets `tool_reference` blocks and Antigravity declares them from the first request, and the model calls them at once. Background: `{id, session}` returns at once (`bg1`, `bg2`, ... per parent session); the child's answer (with its stats line, cut to `outputBytes`) reaches the parent as a steer `[subagent <id> finished] ...` at the next step boundary; a turn that ends `Done` while background children run waits for them, each answer starting a new turn (inbox input still arrives, pause and cancel end the wait); a turn that ends otherwise leaves them running and the next turn gets their answers. `agent_send(id, text)` steers a child (its inbox), `agent_stop(id)` sets its cancel flag, `agent_output(id, wait)` returns its full answer. `maxParallel` counts the running children of one session: a foreground call waits for a place (until cancel), a background call is an error at once. Registries live per session id for the process (`agent::Children`), so a front end's per-turn agent finds earlier children. Events: `AgentEvent::Subagent {session, running}` and `AgentEvent::SubagentProgress {session, line}` (`label · step N · tool`, at most every 500 ms per child) go up from every descendant; the parent forwards them while its tools run, at step boundaries and while it waits; the TUI and GUI show them through `view::Transcript` as one info note per child session, updated in place. Cancel: a foreground child shares its parent's flag; when a turn ends with the flag set, every background child is cancelled (each passes it on) and awaited up to 30 s.
