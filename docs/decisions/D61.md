# D61: Typed trace records and the transcript parity table

Owner decision, 2026-11-13: `docs/architecture-plan.md` gate G8, options a and b; option c not taken.

## a. One table for live and replay
`crates/fast-harness-core/tests/view_parity.rs` runs scripted turns through the real agent loop with a sink feeding `Transcript::apply`, rebuilds the transcript from the log with `Transcript::from_trace` and compares the whole value. Cases (`tests/view_parity/cases.rs`): plain text, thinking then text, one tool, parallel reads and a serial write, tool errors, a steer in a tool step, a follow-up and a next turn, a cancelled turn, a paused then resumed turn, a retry, an account switch, a manual and an automatic compaction, a subagent, a failed turn, `find_tools`, a spilled result, an approval allowed and one declined (trace version 11, D64).

The table found four replay bugs, all fixed in `view/replay.rs`:
- `turn_usage` was never summed on replay (the status line lost the cache rate after an open).
- `turn/end` notes used the logged word (`paused`, `step_limit`) instead of the live text.
- A failed turn's error (`assistant/attempt` with no retry or switch after it) did not show.
- A compaction at a turn start showed before the user's text; live shows the text when it is sent.

Normalised, live only by design: `revision`, `state`, and the subagent notes (`AgentEvent::Subagent` has no log event; the child's own log holds its work).

## b. Typed records
`trace::Record` (`trace/record.rs`) has one variant per event type; its serialised form is the line's `data`, keys sorted as the untyped writer wrote them (serde_json without `preserve_order`). `TraceWriter::write(&Record)` writes one; the `TraceWriter` event methods are constructors over it; `TraceEvent::record()` reads one.

Unknown lines: a type this build does not know, or a known type whose data has a key it does not know (`deny_unknown_fields`), lacks a required key or has another value type, reads as `Record::Raw { kind, data }` and writes back unchanged. Keys a version added are `Option`s left out when `None`; keys written as `null` are `Nullable` (missing, `null` or a value), so every read record writes the same bytes.

Readers: every reader outside `trace/` matches on `Record` (`agent/conversation.rs`, `session.rs`, `session/unfinished.rs`, `session/compacted.rs`, `stats.rs`, `reflect.rs`, `view/replay.rs`, `fast-harness/src/tail.rs`), and `tests/guard_rails.rs` fails when a non-test source file outside `trace/` reads an event's `data` by string key. `trace/detail.rs` and `trace/report.rs`, inside `trace/`, still read by key. One behaviour follows from `Raw`: a line that lacks a required key was half-read by the untyped readers and is now skipped like a line of an unknown type (`view/replay.rs`); no line of the 38 real logs is such a line.

Proof: `tests/trace_record.rs` writes every event type through the typed path and through the data the old functions built and compares the lines (time masked); `FAST_HARNESS_ROUNDTRIP_DIR` runs a byte-for-byte round trip over a copy of real logs (2026-11-13: 38 logs, 1097 lines, none raw, none changed).

## Why not c
One reducer (`Logged(Record)` as the only event) would remove `from_trace` and half of `apply`, but changes the `AgentEvent` contract and every front end at once; the parity table gives the same guarantee for now.
