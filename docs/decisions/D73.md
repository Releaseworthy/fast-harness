# D73 Step summaries in the GUI chat

Owner request (2026-11-14): the chat should not show every detail by default.

- `chatDetail` (config, default `summary`; `full` keeps the old rows; any other value reads as `summary`). Settings > Appearance switches it at once and saves it.
- A step is the run of items from after a user message or step footer to the next step footer (`view::step_range`). `view::summarize` counts its calls once per step update: the shown line uses DSH wording without numbers ("Thought, ran commands, read files, 1 failed"), the accessible label has the counts ("ran 2 commands"). Failures, gate-ended calls and the running call are words; the line also carries an error mark and a spinner.
- The line sits on the step's first assistant or tool row (`src/step_rows.rs`); the other rows fold (tool cards, footer, thinking; assistant text stays). A tool waiting for approval never folds; the approval card is outside the transcript anyway.
- Click, Enter or Space on the line opens the step: its rows show as in `full`, indented right of a faint rail (12 px hit area, "Collapse step") whose click folds it again. Open steps live in the `Mirror` (kept across syncs, cleared on a session switch).
- Performance: the mirror recomputes the lines of the current turn's steps on each sync and writes only rows whose item, word or step part changed; nothing is computed per frame.
