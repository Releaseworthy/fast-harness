# D49: Session coordination

Owner, 2026-11-12: "tao muốn mọi thứ đều custom và chỉnh sửa được" (docs/efficiency-plan.md phase 16 part 2, `docs/service.md` "Session coordination"). No daemon: a top-level session running a turn in any front end keeps `<id>.lock` and `<id>.inbox.jsonl` next to its log. `session::lock`: `Lock {pid, started (process creation time, `platform::process_start`), program, id, cwd, since, state (running, pausing, stopping), turn, step}`, `Held::take` writes it through a temporary file and rename when `Agent::turns` starts (`Inbox::attach`, depth 0 only), `update` rewrites it at each step, drop removes it while it is still ours; `live_lock` removes a stale one; `running(home)` (ps), `find(home, id)` (any directory), `wait`. `session::coord`: `Command::{Steer, FollowUp, Pause, Stop}` as JSON lines (`type` `steer`, `follow_up`, `pause`, `stop`), `append` (one write), `FileInbox::poll` (one size check, whole new lines from the last offset). `Inbox::boundary(turn, step)` runs once at the top of every step loop and before the next follow-up turn: lines go into the D39 queues; `stop` ends the turn `Cancelled` at the boundary and stops background children (`Inbox::stopped`). `Inbox::detach` reads once more, deletes the inbox file, drops the lock; lines written while idle are read by the next turn. `Service::send_to(id, text, Mode::{Steer, Queue}, sink)`: a live lock gets an inbox line (`Sent::Queued`), else this process resumes the session and runs the turn (`Sent::Ran(Finished)`). CLI: `send <id|latest> <text> [--steer|--queue] [--wait]`, `ps [--json]`, `stop`, `pause`, `wait`, `tail [--json]` (text lines or raw events, followed every 250 ms while locked), `start [--model M] [--cwd D] <prompt>` (creates the session, prints its id, `agent::worker::Launch::worker` builds `fast-harness -p <prompt> --resume <id> --cwd D [--model M]`, `platform::spawn_detached`: `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`, with `CREATE_BREAKAWAY_FROM_JOB` when the job allows it, null stdio). Model tools (`agent::session_tools`, added with `subagent` so a child below `maxDepth` keeps the parent's list; deferred, D30): `sessions_list`, `session_start`, `session_send` (idle: a worker runs it), `session_read` (state and last answer under the D37 budget), `session_stop`; the `Launcher` is injectable (tests record launches). Limits: stop and pause act at step boundaries; another user's process looks stale; without `/proc` (non-Windows, non-Linux) every lock looks stale.
