# D79 Subagent sessions are full sessions

Status: part 1 done (2026-11-14): core live controls, session lock, index parent, GUI routing, Back tab. Part 2 done: the popover's model, effort and token line, a live event pump instead of the log reload. Follows: GUI tests of the pump, the child's enabled composer and Back on a top-level session, screenshots, the live smoke.

## Decision

A subagent's session is a session like any other: the owner can prompt it, steer it, pause it and stop it from the GUI, at any depth. It leaves the sidebar (it is reached from its parent's Subagents popover) and, while it shows, a Back tab sits before Chat ("Back to <label>", cut at 220 px, the full text is the accessible label) and returns to the parent session. The read-only notice of D74 is gone: the composer is enabled in a child.

## Core

- `agent/live.rs`: a process-wide registry of the children running now inside a parent's turn. `running`, `steer` (an inbox steer of the child), `pause` (at its next step boundary), `stop` (only the child: the parent's turn goes on and gets the cancelled result) and `watch` (an mpsc receiver of every later event of the child; it closes when the child ends). `Forward::event` in `child_run.rs` publishes each child event to the watchers.
- A foreground child has its own cancel flag, linked to the parent's by a scoped watcher thread polling every 50 ms, and its own inbox, so a stop or a pause of the child leaves the parent alone while a stop of the parent still reaches every descendant.
- One turn per subagent session: a turn at depth > 0 calls `live::enter`; a second turn of the same session (a front end continuing a child its parent still runs) is refused with "running a turn already" and ends `Failed`.
- Subagent sessions take the session lock like top-level ones (the depth > 0 exemptions in `inbox_file.rs` attach and `running_elsewhere` are gone); `send_message` to a live child becomes an inbox steer.
- `SessionSummary.parent` (the header's parent) and `session::top_level` (the list without children); the session index is version 3 (`docs/formats.md`).

## GUI

- `listings.rs` lists `session::top_level`, so children leave the sidebar.
- `turn.rs`: Send, Pause and Stop of a shown session that `live::running` reports go to `live::steer`, `live::pause` and `live::stop`; otherwise a child session (finished or never run in this process) runs its own turn like any session.
- `SubagentsUi.in-child` replaces `read-only`; `BackTab` in `ui/panel.slint`; `SubagentRow.detail` is a dim second line of a popover row: the model's picker name (`Catalog::display_name`, else the id), the effort and every token of the child's log (input, output, cache read and write, `short_tokens`), read by `session::children` (`Child.model`, `effort`, `tokens` from the latest `request/context` and every `assistant/message`). While the popover is open a running child's progress scans again at most every 2 s, so the tokens grow live.
- `child_pump.rs`: a running child shown in the chat view follows `live::watch`: a thread hands each event to `turn::deliver` on the UI thread, the run is busy meanwhile (Stop, Pause and the composer reach the child through `live`), and when the channel closes the run goes idle and its log opens again (`open_load::reload`), so the service session holds the whole conversation. Events between the log's load and the watch start show only after that reload.
