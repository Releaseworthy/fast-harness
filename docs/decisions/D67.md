# D67: Registries become values

Owner, 2026-11-13: phase 27 (docs/architecture-plan.md finding D4). Four process-wide statics held what belongs to one runtime or one session: the custom providers of `providers/*.json` (`llm/custom.rs`, never removed, ids and titles leaked with `Box::leak` for `&'static str`), the live model table (`llm/anthropic/live.rs`), the children of every session id (`agent/children.rs`, never pruned) and the installed plugins (`ext/mod.rs`). A trusted project's provider stayed for every other workspace of the process, and two runtimes in one test process shared all of them.

## Decision

- **`llm::Catalog`.** A value owned by `app::Runtime` (field `catalog`): the provider files of the loaded settings (`Arc<Vec<ProviderFile>>`, a later file with the same id wins) and the live model table (`Arc<anthropic::LiveModels>`). Cloning is two `Arc` increments. Its methods replace the free functions of `catalog` and `custom`: `provider_of`, `providers`, `group_title`, `grouped`, `model`, `price`, `efforts`, `fit_effort`, `context_window`, `display_name`, `max_output_override`. Ids and titles are borrowed from the catalog (`&str` tied to it); nothing is leaked.
- **Reload makes a new catalog.** `Runtime::apply` (every settings load, `use_project`) sets `catalog = catalog.with_files(..)`: a new file list sharing the live table. A second workspace in one GUI process no longer sees the first's providers, and an agent built before keeps the providers it started with.
- **Live models.** `LiveModels` is a value (`remember`, `lookup`). The runtime's `Anthropic` provider holds the same `Arc` (`Anthropic::with_live`), so `GET /v1/models` and the `models.json` cache (`app::load_cache`) fill that runtime's table only, and the request builder plans thinking from it. `anthropic::{efforts, fit_effort, context_window}` take the table. A bare `Anthropic::new` gets an empty table of its own. An `anthropic-messages` custom provider shares the runtime's table, as it shared the static one; an `openai-chat` one holds its own file's model entries (`OpenAiChat::with_models`).
- **Who gets it.** `AgentParts.catalog` (compaction window, `maxOutput` cap, a subagent's provider check), `ModelSource` (custom model rows), `app::pickers` (`model_list`, `effort_list`, `refit`, `merge` take `&Catalog`), `service::Host::catalog(cwd)` (config options and `stats` of `serve`, the GUI and the TUI; the default is an empty catalog), the TUI (`Ui.facts`, set from the runtime at start), the GUI (`app.rt.catalog`), `fast-harness models`, `-p` (`PrintHost` keeps the agent's), reflect (`pick_model`) and `stats::compute_with`. `stats::compute` prices nothing, as `fast-harness stats` did before (that command never loaded the provider files).
- **Children.** The table stays keyed by session id (session ids are unique per log, so runtimes never share an entry), but `Service::close` now calls `children::forget(id)`: the entry goes and its background children are cancelled. GUI and TUI close, `session/close` of `serve` all go through `Service::close`. A `-p` run ends with the process. It stays a static because the agent layer reaches it by session id from code that has no runtime (layering: `agent` sits below `app`).
- **Stays static: installed plugins.** `ext::INSTALLED` is set once at start from the plugins compiled into the binary (`fast_harness_plugins::install`); it is the same for every runtime and workspace, never grows and holds no per-workspace data, so it stays a set-once `OnceLock`.
- **Stays: `live::static_levels`.** It maps level names to the `LEVELS` constants; those `&'static str` are literals, not leaked memory.
- **No file format change.** `providers/*.json`, `models.json` and the trace are unchanged.
- **Guard.** `tests/catalog_values.rs`: two runtimes with different providers (ids, titles, owners, model rows), a project's provider gone after `use_project` to another folder, live models of one runtime absent from another, a closed session's children entry gone, and no `Box::leak` or `static REGISTRY` in `fast-harness-core/src`.
