# D82: Subagent models and model guide

Date: 2026-11-14. Area: crates/fast-harness-core (config, `subagent` tool, catalog), crates/fast-harness-gui (Settings).

## Decision

- `subagent.models` (default `{}`): a map from model id to `false` for each model a subagent may not run on. A model missing from the map is enabled, so every known model is enabled by default and a model added to the catalog later starts enabled. `SubagentConfig::allows(id)` reads it.
- The models a subagent may name are `Catalog::model_ids()`: the built-in Claude table, then ids only the live list (or `models.json` cache) knows, then `<provider>/<id>` of every custom provider; dated snapshots (`-20251101`) are left out (their undated alias stays).
- The `subagent` tool's `model` property carries `"enum": [<enabled ids>]` (no `enum` when none is enabled). `child_run::build` checks the resolved model (the call's `model`, else the agent type's, else `subagent.model`, else the parent's) and refuses a disabled one before a child session exists: "model `X` is disabled for subagents (setting subagent.models); enabled models: ...". A call without `model` whose default is disabled is refused the same way and told to pass `model`.
- `subagent.guide` (default below) is appended to the tool description after a blank line. A guide line that names only model families (`haiku`, `sonnet`, `opus`, `fable`, case-insensitive) of which no enabled id contains the word is left out; when every family line is left out the guide is dropped. `""` sends no guide. Default:

  ```
  Pick the subagent's `model` by what the task needs:
  - Haiku: search and read news, docs and data.
  - Sonnet: small, well-scoped fixes.
  - Opus: harder, complex or open-ended work.
  ```

- The tool list stays frozen per session (D36): the enum and the guide reach new sessions; the refusal check reads the current setting, so a model turned off in Settings is refused from the next call of a running session.
- Settings > Subagent models (`ui/spawn_settings.slint`, `SpawnUi`, `src/spawn_settings.rs`), the section after Subagents: one check box per `Catalog::model_ids()` entry (name and id, "on"/"off" in words, accessible role checkbox) and a multi-line guide editor with Save, Reset to default (writes the default text) and an "Unsaved changes" mark, like the system prompt editor. Each change goes through `config::save_section_setting` (`store::update`, D55); the models map keeps only the `false` entries.

## Tests

- `agent/spawn_models_tests.rs`: all models enabled by default, a disabled model leaves the enum and is refused (asked and default), guide lines of disabled families dropped, config round trip with defaults.
- `tests/subagent_models.rs`: on the wire (`ScriptedTransport`), the `subagent` tool's enum lacks the disabled model, its description ends with the configured guide, and the call's tool result is the refusal with no child request.
- GUI `src/spawn_settings_tests.rs`: a check box writes `subagent.models`, Save and Reset write `subagent.guide`, the running config follows.
