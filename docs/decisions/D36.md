# D36: Frozen prefix

Owner, 2026-11-12 (docs/efficiency-plan.md phase 11, G3 "G3 theo plan"). `Conversation` holds `system` and `tools`: set on the first turn of a new session (`Runtime::agent` renders the prompt from the files and AGENTS.md only then) and restored from the last `request/header` on resume, so every request of a session sends the same system text and tool list (names, descriptions, schemas); a tool added later belongs to new sessions. A change of the prompt sources (the date passed midnight UTC, a prompt file edited, the workspace override toggled, an AGENTS.md added, edited or removed) is compared with the stamp kept in `request/header` `context` (date, FNV-1a hashes of the template with its source and of each AGENTS.md) and goes once, as one text block ahead of the next user text: `[context update] Today is 2026-11-13.`, `[context update] The system prompt changed (<source>); follow this text from now on:` plus the filled template, `[context update] <path> changed; it now reads:` (or `was added`) plus the file text, `[context update] <path> was removed; its instructions no longer apply.`; lines are separated by a blank line and the block is capped at 64 KB. A resume reads the moved stamp and never repeats a note. The GUI prompt editor says "applies to new sessions; running sessions get a note". Antigravity `request.sessionId` is `-<FNV-1a of the conversation id mod 9e18>` (stable per session, distinct per subagent; the provider's random id only without a conversation). `Managed` models keep `drop_block` until `stats --all` shows zero `prefix_binding_mismatch` across real sessions; then the tests and the request send `"error"`. Stop reasons: `max_tokens` ends the turn `Truncated` (TUI and GUI note "truncated: the answer hit the output token limit", print mode a note and exit 1), except once per turn when the cut message holds a tool call whose arguments are not complete JSON: that call gets its error result and the turn goes on; `pause_turn` goes on with the paused message sent back; `model_context_window_exceeded` and a 400 or 413 "prompt is too long" end the turn `ContextOverflow` with a clear error, no retry (phase 13 compacts there). `cacheTtl` `"5m"`, `"1h"` or `"auto"` (default; `cacheLong: true` reads as `"1h"`): `auto` puts 1 hour on the tools and system breakpoints always and on the message breakpoint in the TUI and GUI (`Runtime.interactive`), 5 minutes in print mode and subagents.
