# GUI, Slint, window and icon pitfalls

- Slint 1.18.1 StyledText is not selectable: the GUI copies through a hidden TextInput.
- Slint 1.18.1 std-widgets colours are read only (only `Palette.color-scheme` can be set) and follow the OS accent: use the themed widgets in `ui/widgets.slint`, not Button, TextEdit, ComboBox or StandardTableView.
- GUI icons come only from the embedded "Fast Harness Icons" font (a Nerd Font subset, `crates/fast-harness-gui/fonts/`), named in `ui/icons.slint`: a new glyph needs the subset rebuilt with its code point (`fonts/NOTES.md`). Check glyphs in the shots test (`FAST_HARNESS_SHOTS_DIR=<dir> cargo test -p fast-harness-gui shots -- --ignored`).
- `WindowMoveArea` delays the press, so a TouchArea double click inside it never fires: the title bar double click and every window state change go through `src/window_state.rs` (the .slint `maximized` property drifted from the real state); a winit `Resized` re-reads it (`src/window_events.rs`), never a polling timer (a 200 ms one woke the idle window about 150 times per 30 s).
- A window keeps only one `on_winit_window_event` hook (a second call replaces the first): every winit event handling (dropped files, resize, caret rest) lives in `src/window_events.rs`.
- Slint 1.18.1 blinks the caret of a focused TextInput with a repeating timer for as long as it thinks the window is active, one frame per blink, and offers no switch (the flash cycle is a `Platform` method of the winit backend, not re-exported by `slint`). `src/window_events.rs` rests it after the caret timeout (`platform::caret_timeout`, 5000 ms default) by dispatching `WindowActiveChanged(false)` while the composer has focus, and `true` before the next input: `has-focus` is false meanwhile (the composer keeps its look through `Caret.resting`), and a rest during an IME composition would clear the preedit, so it waits for the commit. A script-started window may never get winit `Focused(true)`: arm nothing on it.
- Real-window checks: `scripts/window.ps1` (start, shot, click, move, wheel, drag, key, type, size, close) on a copy of the release exe with `FAST_HARNESS_HOME` set to a fresh temp folder; PrintWindow and posted input after SetProcessDPIAware, in physical pixels. winit drops a bare posted WM_CHAR (type posts key down, char, key up), a posted move does not keep hover (WM_MOUSELEAVE follows), and posted clicks cannot move or resize the window. In pwsh 7, `Add-Type` C# that uses System.Drawing fails to compile: keep only the P/Invoke in C#.
- Slint's window `icon` sets only ICON_SMALL on the frameless winit window: the taskbar and Alt-Tab icon comes from `fast_harness_core::platform::set_big_window_icon` (WM_SETICON ICON_BIG from the exe's icon group 1).
- The main card clips its children to the rounded corner and draws its border in an overlay after them: a border on the clipping rectangle itself left a gap along the curve.
- The folder picker declares the IFileOpenDialog and IShellItem vtables by hand (`platform/windows/folder.rs`): check GUIDs and method order against the `windows` crate source before changing them.
- The software renderer lays text out in i16 physical pixels (`PhysicalLength` in `i-slint-renderer-software` 1.18.1): a Text taller than 32767 px overlaps itself. Every long transcript or trace text goes through `trace_rows::expanded` (300 lines or 12K characters with a note; Copy keeps all).
- A mouse wheel on a ListView fires `scrolled` before its 180 ms animation moves the content, and the std scroll bar never fires `scrolled`: the transcript treats any user scroll as leaving the bottom and follows again only at the bottom or after "Jump to latest" (`ui/transcript.slint`, `src/scroll_tests.rs`). Long lists use the themed bar in `ui/scrollbar.slint` (the ListView's own bar off); its drag moves by the share of the track, since a pixel-offset drag snapped back while the ListView re-measured rows.
- Software renderer limits (`i-slint-renderer-software` 1.18.1 `lib.rs`): gradient fills ignore `border-radius`, clips are square ("TODO: handle radius"), `draw_box_shadow` draws nothing and a gradient window background comes out solid. Rounded gradients are built from solid rounded caps and a square band (`AccentFill` in `ui/parts.slint`), elevation and glow from stacked translucent rounded fills.
- Slint 1.18.1 measures a repeated plain element (an `if` or `for` whose root is a Rectangle or a layout) at its unwrapped width, so its wrapped text gets one line and the next row draws over it ([slint#13655](https://github.com/slint-ui/slint/issues/13655), fixed after 1.18.1): wrapped text under an `if` or `for` sits in a component (`ui/blocks.slint`). A component that places `@children` next to its own wrapped text measured that text as one line too (the first tool card, 2026-11-12): build such parts in. `src/layout_tests.rs` guards both in the .slint files and measures the rows.
- Tool cards (D34): `view::tool_detail` (core) gives each tool call its facts; `src/tool_rows.rs` maps them, `ui/toolcard.slint` and `ui/codeview.slint` draw them. Tinted backgrounds under text need a `theme::TINTS` entry: success and error marks on the 0.12 diff tint fail in five built-in themes, so diff marks stay in the text colour.
- `ui/widgets.slint` is close to the 500-line limit: put a new widget in its own file (as `ui/controls.slint` and `ui/scrollbar.slint`). A Rectangle that stacks Card layers around a layout needs its `preferred-height` from that layout.
- Colours come only from `fast_harness_core::theme` roles (TUI `tui/theme.rs` Styles, GUI `Theme` global): no literal colours besides the neutral popup shadow. A palette change must keep `theme_tests.rs` green (WCAG 2.2 and APCA levels for every built-in theme at greyscale 0 to 100, pure grey at 100), and every status colour comes with a mark or a word. Built-in themes are JSON files (`crates/fast-harness-core/src/theme/builtin/`) in the same format users write (`docs/themes.md`, D33): a new or renamed role is a format change.
- TUI Nerd Font glyphs must be one cell wide (the width test in `tui/icons.rs`): U+26A1 is double width.
- Opening the TUI creates a session file even if nothing is sent.
- The window ignores the Windows display scale (D75, `src/display.rs`): `SLINT_SCALE_FACTOR` is set before the window exists and `window_events` keeps the physical size on `ScaleFactorChanged`. The default renderer is Skia on Direct3D 12 with vsync (D78; FemtoVG with vsync before): the software renderer tears (GDI blits, no vsync) and draws no drop shadow, so shadows are one `drop-shadow-blur` (flat there), never stacked translucent fills (they read as ghost edges).
- Subpixel text (D78) comes from `vendor/i-slint-renderer-skia`, Slint's Skia crate pinned to 1.18.1 with four lines marked `Fast Harness patch (D78)`: a Slint update re-copies the crate from the registry and re-applies them (D78 lists them), or drops the patch once Slint sets the surface pixel geometry itself (slint#5748). LCD text needs an opaque destination: keep text on opaque fills (Skia's behaviour in a translucent `opacity` layer was not checked). The prebuilt Skia library needs two MSVC STL helpers that MSVC 14.42 lacks (`platform/windows/stl_shims.rs`).
