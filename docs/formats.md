# Fast Harness formats

The formats code comments cite by section name, moved here unchanged from `PLAN.md` on 2026-11-13: the files on disk, the trace format, the account rules and the tool output texts. A format changes only with a version bump and an update of its text here in the same commit.

## Files on disk

> On `main`: `antigravity-models.json`, `google-client.json` and `google-usage.json` belong to branch `antigravity` (a143cfa, [D53](decisions/D53.md)); main does not read them.

- `~/.fast-harness/config.json`: model, effort, `cacheTtl` (`"5m"`, `"1h"` or `"auto"`, the default, D36; the older `cacheLong: true` still reads as `"1h"` when `cacheTtl` is absent), limits, `theme` (colour theme id, built-in or user; `greyscale-dark` and `greyscale-light` load as `dark` and `light` with greyscale 100), `greyscale` (0 full colour to 100 pure greys, applied to every theme, default 0; a number is rounded and clamped, anything else reads as 0), `icons` (TUI icon set: `"nerd"` Nerd Font icons, the default, or `"plain"` Unicode marks) `wire` (raw wire capture, default `false`), `toolOutputBytes` (byte budget of one tool result, default 8192, D37) and `toolOutput` (budgets per tool name, e.g. `{"read": 16384}`), `compaction` and `models` (per provider or model `compaction` overrides, D38). `FAST_HARNESS_MODEL`, `FAST_HARNESS_EFFORT`, `FAST_HARNESS_THEME`, `FAST_HARNESS_GREYSCALE`, `FAST_HARNESS_ICONS` and `FAST_HARNESS_WIRE` override it; `FAST_HARNESS_HOME` moves `~/.fast-harness`.
- `~/.fast-harness/themes/*.json` (version 1, D33, `docs/themes.md`): user themes, one per file, `{"version":1,"id","name","kind":"dark"|"light","extends"?,"colors":{"<role>":"#rrggbb"}}`; read at start and on Reload, listed after the built-ins in file name order. A file with a built-in id or an earlier file's id is skipped with a note; a broken file is reported and the others still load; a theme failing the contrast check loads with a warning listing the failing pairs. Readers reject any other version.
- `~/.fast-harness/trusted.json` (version 1, D41): `{"version":1,"paths":[...]}`, the trusted projects; a newer version reads as nothing trusted, is never rewritten, and `doctor` names it. `~/.fast-harness/providers/*.json` and, in a trusted project, `<project>/.fast-harness/config.json` and `providers/*.json` (D41, `docs/extending.md`).
- Extension files (version 1, phase 29, `config/ext_file.rs`): `config.json`, `hooks.json`, `keys.json`, `mcp.json`, `tools/*.json`, `providers/*.json`, `panels/*.json` take a top-level `"version"`, and `agents/*.md`, `commands/*.md`, `skills/<name>/SKILL.md` a front matter line `version: 1`. Absent reads as 1; a higher number is skipped with the reason `version N is newer than this build reads (1)` (a newer user `config.json` stops the start, as any bad user `config.json` does). Every one of them except `config.json` also takes `"enabled": false` (front matter `enabled: false`), which skips the file with the reason `disabled`; tool files keep `"disabled": true` as an alias, and off wins when both are set. Themes keep their own version (`docs/themes.md`).
- `~/.fast-harness/models.json`: the last model list from `/v1/models`, `{"version":1,"fetchedAt":<unix ms>,"models":[{id, displayName, contextWindow, maxOutput, reasoning, efforts, deprecated, live: {effort, adaptive, budget, canDisable} or null}]}`; written after each successful list (temp file, then rename), read at start; a corrupt file or another version is ignored.
- `~/.fast-harness/antigravity-models.json` (version 1, D24): the last Antigravity catalog, `{"version":1,"fetchedAt":<unix ms>,"models":[{id (bare), displayName, contextWindow, maxOutput, supportsThinking, supportsAdaptiveThinking, thinkingBudget, thinkingLevel}]}`; written after each successful `fetchAvailableModels` list (temp file, then rename), read at start into the Antigravity catalog registry and shown after the Claude models in the pickers; a missing, corrupt or other-version file is ignored.
- `~/.fast-harness/accounts.json` (version 3, D26): `{"version":3,"active":<Anthropic id>,"activeGoogle":<Google id, omitted when none>,"accounts":[...]}`; each account has `provider` (`anthropic` or `google`): Anthropic own and API-key accounts, Google accounts (`kind: own`, id `g-<Google user id>`, plan = tier name). Secrets encrypted (DPAPI on Windows): `own` {refresh, access, expiresAt}, `apiKey` {key}, `google` {refresh, access, expiresAt, projectId}. Version 2 is version 3 without `provider` and `activeGoogle`: its records load as `anthropic`. Version 1 also held linked accounts: they are dropped on load (an `active` pointing at one falls back to the first remaining account). The next save writes version 3. Readers accept versions 1, 2 and 3 and reject any other.
- `~/.fast-harness/google-client.json` (D25): `{"version":1,"id":"<client id>","secret":"<base64 of the encrypted secret>"}`, written by `fast-harness accounts google-client --id <id>` (secret from stdin); `FAST_HARNESS_GOOGLE_CLIENT_ID` and `FAST_HARNESS_GOOGLE_CLIENT_SECRET` win over it. Readers reject any other version.
- `~/.fast-harness/google-usage.json` (version 1, D23): the last quota read of each Google account, `{"version":1,"accounts":{"<id>":{"readAt":<unix ms>,"groups":[{"name":"Gemini Models","fiveHour":{"used":<0..1>,"resetsAt":<unix ms, omitted when unknown>,"disabled":false},"weekly":{...}}]}}}`; written after each successful read (temp file, then rename), read at start so the Accounts page shows the last read; a missing, corrupt or other-version file is ignored.
- `~/.fast-harness/workspaces.json` (version 1): the sidebar's workspace folders, `{"version":1,"workspaces":[{"path":"F:\\work\\x","addedAt":<unix ms>,"lastUsedAt":<unix ms>}]}`, listed in `addedAt` order, one entry per session slug. A missing file is seeded from every `sessions/<slug>/` folder (the `cwd` in the header of its newest log); written temp file then rename; a corrupt file or another version is an error (shown, and the file is left alone). Removing a workspace never touches its sessions.
- `~/.fast-harness/system-prompt.md` (D31): the global system prompt template, plain text with `{cwd}`, `{os}`, `{date}` and `{model}`; written by Settings > System prompt (temp file, then rename), deleted by Reset to default. Read for every new session, and when each turn starts only to detect a change for a running session (D36); an unreadable file is skipped with a note (the next source applies).
- `~/.fast-harness/prompts/<cwd slug>.md` (D31): one workspace's template (same slug as `sessions/`), it wins over `system-prompt.md`; written when Override global is turned on (starting from the global text) or saved, deleted when it is turned off. `fast-harness prompt [--cwd DIR]` prints which file applies and the rendered prompt.
- `<file>.lock` next to `config.json`, `trusted.json`, `workspaces.json`, the memory files (and `accounts.json`, D55 part B): `{"pid":..,"started":..}`, exists only while a write of `<file>` runs (D55).
- `~/.fast-harness/sessions/<cwd slug>/<session id>.jsonl`: one log per session (transcript and trace).
- `~/.fast-harness/sessions/<cwd slug>/index.json` (version 2, D60; 2 since D70 so cached titles of first prompts with images are rebuilt from the user's words): a cache of the session list, `{"version":2,"logs":{"<id>.jsonl":{"size":..,"modified":<ns since 1970>,"summary":{"id","createdAt","title","turns","lastTime","unfinished"?:"interrupted"|"paused"|"cancelled"}|null}}}`; `summary` is null for a log that does not read. Written by a list through `store::update` (with `index.json.lock`) only when an entry changed; a log whose size and modified time match its entry is not read. Missing, damaged or another version: rebuilt; unwritable: the list answers without it.
- `~/.fast-harness/sessions/<cwd slug>/<session id>.out/<callId>.txt` (D37): the full text of each tool result cut to its budget.
- `~/.fast-harness/sessions/<cwd slug>/<session id>.wire/`, only with wire capture on: per model call attempt, the request (headers with credentials redacted, body) and the raw response stream.

## Trace format

One JSON object per line. A header line, then events `{type, seq, time, data}`; `time` is Unix milliseconds, `seq` counts from 0. Event names follow the DSH session log.

```
{"type":"session","version":3,"id":"...","createdAt":1794400565123,"cwd":"F:\\work","harness":"fast-harness 0.1.0","parent":null}
{"type":"turn/start","seq":0,"time":...,"data":{"turn":1}}
{"type":"user/message","seq":1,"time":...,"data":{"turn":1,"message":{...}}}
{"type":"step/start","seq":2,"time":...,"data":{"turn":1,"step":1}}
{"type":"request/header","seq":3,"time":...,"data":{"system":"...","tools":[...]}}
{"type":"request/context","seq":4,"time":...,"data":{"turn":1,"step":1,"attempt":1,"provider":"anthropic","model":"claude-opus-5-5","account":"u-1f3c","effort":"high","wire":"t1-s1-a1"}}
{"type":"llm/retry","seq":5,"time":...,"data":{"turn":1,"step":1,"attempt":1,"delayMs":2000,"error":"Overloaded (HTTP 529): ..."}}
{"type":"account/switch","seq":6,"time":...,"data":{"from":"u-1f3c","to":"u-77ab","reason":"RateLimit","holdUntil":...}}
{"type":"assistant/message","seq":7,"time":...,"data":{"turn":1,"step":1,"message":{...},"usage":{"inputTokens":4,"outputTokens":363,"cacheReadTokens":0,"cacheWriteTokens":24114},"stop":"tool_use","timing":{"ttfbMs":812,"firstTokenMs":1190,"totalMs":5100,"chunks":96,"bytes":18233},"account":"u-1f3c"}}
{"type":"tool/call","seq":8,"time":...,"data":{"turn":1,"step":1,"callId":"toolu_...","name":"read","arguments":"{...}"}}
{"type":"tool/result","seq":9,"time":...,"data":{"turn":1,"step":1,"message":{"role":"tool","content":[...]},"durationMs":3,"bytes":412}}
{"type":"step/end","seq":10,"time":...,"data":{"turn":1,"step":1,"durationMs":5120}}
{"type":"turn/end","seq":21,"time":...,"data":{"turn":1,"steps":3,"usage":{...},"durationMs":14200,"outcome":"done"}}
```

- Version 2 (2026-11-11): `request/context` has the `wire` key (the attempt's capture name) only when wire capture is on; version 1 always had it. New logs are version 2; a resumed version 1 log keeps its header. Readers accept versions 1 and 2 and reject any other.
- Version 3 (2026-11-12): assistant messages carry `model` (the full model id); `tool_call` blocks may carry `signature` (a Gemini thought signature). New logs are version 3; readers accept versions 1 to 3.
- Version 4 (2026-11-12): `assistant/message` has `context` and `window`; usage may have `cacheWrite1hTokens` (absent when 0); `request/transformations` (`{turn, step, transformations, prefixBindingMismatch}`) is written before `assistant/message` when Claude reports `input_transformations`; `compaction` is reserved for compaction. New logs are version 4; readers accept versions 1 to 4.
- `fast-harness stats [ID|latest|--all] [--json] [--cwd DIR]` reads the logs for context and cache numbers (D35).
- Version 5 (2026-11-12, D36): `request/header` may carry `context` (`{date, prompt, agents: {path: hash}}`, the stamp of the prompt sources) and is written when the system prompt, the tool list or the stamp changes; the last one is the frozen system and tool list a resume replays. A user message may start with a `[context update]` text block. `turn/end` `outcome` may be `truncated` or `context_overflow`; `stop` may be `pause_turn` or `context_window`. New logs are version 5; readers accept versions 1 to 5.
- Version 6 (2026-11-12, D37): `tool/result` has `bytes` (the size of the full output before the budget cut it) and, for a cut result, `spilled` (the path of `<session>.out/<callId>.txt`); a read result may be `[unchanged since call <id>]`. New logs are version 6; readers accept versions 1 to 6.
- Version 7 (2026-11-12, D38): `compaction` (`{turn, step, summary, facts, loaded, callId, mid, before, after, usage, auto, model, instructions}`) replaces the history before it: `session::replay` rebuilds `session::compacted::history(summary, loaded, callId, mid)` there and goes on with the later events; the views keep the whole transcript with a "compacted" divider. On a turn's first step `request/header` comes before `user/message` (it carries the context stamp). The summary request writes `request/context` (and `assistant/attempt` on failure) but no `assistant/message`; its usage is in the event. New logs are version 7; readers accept versions 1 to 7.
- Version 8 (2026-11-12, D39): `user/message` may carry `kind` (`steer`, or `context` for a context update on resume): a text added inside a turn; `session::replay` adds its text to the message before it when that holds tool results or user text (as the live turn did), else it is a new user message. `turn/start` may carry `resume: true`: the turn resumes the history and has no `user/message` of its own. `turn/end` `outcome` may be `paused`. A `turn/start` without its `turn/end` marks an interrupted turn. New logs are version 8; readers accept versions 1 to 8.
- Version 9 (2026-11-12, D40): the header may carry `depth` (the nesting level of a subagent session: 1 for a child, 2 for a grandchild; absent means 0). A subagent session started with preloaded `tools` begins with a synthetic `assistant/message` at step 0 holding one `find_tools` call (`callId` `preload_<turn>`, `{"names": [...]}`), its `tool/call` and a `tool/result` `Loaded: a, b` + `(tools loaded from the start)`; it replays like any find. New logs are version 9; readers accept versions 1 to 9.
- Version 10 (2026-11-12, D44): `hook` events `{turn, event, command, ms, decision}` (`decision` is `none` or the answer keys that acted, joined by `,`: `block`, `arguments`, `output`, `context`, `continue`) and `hook/error` `{turn, event, command, ms, error}` for a hook that failed and was ignored. `user/message` `kind` may be `hook`: a hook's `[hook context] ...` text or a Stop hook's continuation, replayed like a steer. New logs are version 10; readers accept versions 1 to 10.
- Version 11 (2026-11-13, D64): `tool/approval` (`{turn, step, callId, decision}`), written after the step's calls and before their `tool/result` lines, one per decided approval request; `decision` is `once`, `session`, `declined`, `cancelled`, `paused` or `refused`. A replayed transcript shows on that call the same word the live one showed (`allowed once`, `declined`, ...); a request a front end answered never appears twice. New logs are version 11; readers accept versions 1 to 11.
- Version 12 (2026-11-13, D69): `undo` (`{turn, restored, removed, forced}`): the user undid the `write` and `edit` changes of `turn` between turns; `restored` and `removed` are the absolute paths put back or deleted (the turn created them), `forced` is true when files changed since that turn were overwritten on request. A replay shows it as a note `undid the file changes of turn N: ...`. The kept prior states live beside the log in `<id>.undo/turn-<n>/` (`manifest.json` version 1 plus `<i>.bin`). New logs are version 12; readers accept versions 1 to 12.
- `request/header` is written only when the system prompt, the tool list or the context stamp changes.
- Version 13 (2026-11-13, D70): a message block may be `{"type":"image","path","mediaType","bytes","width","height"}` (`types::Block::Image`, `types::ImageRef`): an image held by reference, never inline. `path` is the absolute path of `<id>.media/<first 32 hex of sha256>.<png|jpg|gif|webp>` beside the log (written once, same bytes same file); `mediaType` is `image/png`, `image/jpeg`, `image/gif` or `image/webp`; `bytes` the file size, `width` and `height` in pixels. In a `user/message` each image follows a text block `[image N: <type> WxH, <size>, about T tokens]` and the user's text comes last; in a `tool/result` an image follows the `tool_result` block it belongs to (the `read` tool on a png, jpeg, gif or webp file). The bytes are read when a request is built; a missing or changed file is sent as the text `[image not sent: <why>; <label>]`, never an error. A build before version 13 reads such a line as `Record::Raw` (an unknown block type). New logs are version 13; readers accept versions 1 to 13.
- Typed records (D61, no version change): the Rust types of every event's `data` live in `trace::Record`, one variant per type; a line whose type or shape a build does not know reads as `Record::Raw` and writes back unchanged. This text stays the source for other tools.
- Damaged lines (reader rule, D60, no version change): a last line that is not a valid event is a torn write, skipped, and cut when the log is opened to append. A damaged line before it is skipped and reported (`trace::reader::Parsed::skipped`: line number and byte offset); the session opens with one note naming it and the file keeps it. A missing or bad header still fails.
- A failed attempt writes `assistant/attempt` (`{turn, step, attempt, error, timing}`) before `llm/retry` or `account/switch`.
- A subagent writes its own session log whose header has `parent` set to the parent session id and `depth` to its level; the parent's `tool/result` (or, for a background child, the `[subagent <id> finished]` steer) names the child session.
- `fast-harness trace [ID|latest] [--steps] [--json] [--cwd DIR]` prints the timeline of the session (`trace::detail`): each turn, what the user sent, the request header (system prompt and tools), each request (model, effort, account, attempt), the model's thinking, response text and tool calls with their arguments, tool results, the answer metrics, retries, failed attempts, account switches and the turn totals; then one row per step: turn, step, account, model, TTFB, total time, input, output, cache read and cache write tokens, tools with their durations, retries. `--steps` prints only the step table, `--json` the raw header and events.

## Accounts

> On `main`: the Google bullets (Google accounts, Google pool) describe branch `antigravity` (a143cfa, [D53](decisions/D53.md)); main keeps Google records and `activeGoogle` in `accounts.json` unchanged on save.

- Own accounts: OAuth sign-in in the browser (PKCE, loopback callback), refreshed by fast-harness; or an API key. These are the only kinds: claude-switch links were removed 2026-11-11 (D8).
- Google accounts (D23): `fast-harness accounts login --google`: authorize `accounts.google.com/o/oauth2/v2/auth` (PKCE S256, `access_type=offline`, `prompt=consent select_account`, loopback `/oauth-callback`), form posts to `oauth2.googleapis.com/token` with the client id and secret (a refresh answer without `refresh_token` keeps the old one), userinfo v1, then `loadCodeAssist` (project, tier: paid, else current, else the default allowed) and `onboardUser` without a project (10 polls, 5 s apart; fallback project `rising-fact-p41fc`). Control calls (`llm/antigravity/hub.rs`): Hub User-Agent from the manifest version (cached 6 h, fallback 2.29.0, minimum 2.23.0), daily host then sandbox on 404, 408, 5xx or a network error. Quota: `retrieveUserQuotaSummary` groups with 5 h and weekly windows; a missing `remainingFraction` is 0, an unused bucket (fraction 1) has no reset. The Anthropic pool never leases, polls or fails over to Google accounts.
- Google pool (`accounts/google/pool.rs`, `GoogleAuth`, D23): an `AuthSource` over the Google accounts of the same `AccountPool` (one owner of `accounts.json`). Lease: the active Google account unless held, else the best other one (made active); the access token is refreshed when it expires within 5 minutes (refreshed tokens saved encrypted); the project from the secret, else `loadCodeAssist` (saved), else the fallback. Failures: an auth error refreshes once and retries, a second one holds the account 1 hour; a 403 whose message says `validation required` holds it 1 hour as `validation` with the verification URL kept for the UI; a 429 reads the account's quota once (30 s or more after its previous read, not while backed off) and holds it until the reset of the exhausted window in the model's group (`gemini-*`: the group named Gemini, `claude-*` and `gpt-*`: the Claude or GPT group, matched case-insensitively; every group when none matches), else the error's `retry-after`, else 15 minutes. Then the best other account (not held, most fraction left in the model's group, the tighter of 5 h and weekly, unread accounts last) and `Retry`, or `Wait` until the soonest hold ends. Choosing an account (`use_account`) lifts its hold. Quota reads (`poll`): idle accounts at most every 10 minutes, the account a turn used (`after_turn`) 30 s or more after its previous read; a 429 on a read pauses that account's reads 5 minutes, doubling up to 1 hour.
- Live usage: response headers `anthropic-ratelimit-unified-5h-utilization`, `-7d-utilization` (fractions), `-5h-reset`, `-7d-reset` (Unix seconds), `-status`, `-representative-claim`; idle accounts read `GET https://api.anthropic.com/api/oauth/usage`.
- Auto switch (D10), on a 429 or quota error: hold the current account until its window resets (15 minutes when unknown); skip held, rejected, Free plan and exhausted accounts; order the rest with claude-switch's `switchOrder`: unread accounts last; accounts whose 7-day window resets within 48 hours first, lowest 7-day percent first among them; otherwise the soonest 7-day reset; then the emptier 5-hour window; then the emptier fullest window. Install the first that works and retry at once; with nobody left, wait for the soonest hold and retry every minute.

## Tools

read, write, edit, shell (PowerShell on Windows, timeout, the whole process tree is killed), grep (regex, `.gitignore` aware), glob, subagent (a nested agent with its own session log; one level deep).

Outputs carry the facts the views show (D34): write `Wrote {bytes} bytes ({n} lines) to {path} (new file)` or `(replaced {bytes} bytes, {n} lines)`; edit `Replaced {k} occurrence(s) in {path} at line(s) {n, ...}` (at most 10 numbers); subagent ends with `[subagent session {id} · model {m} · {n} steps · tools {a, b} · in {x} out {y}]`; read ends with `[lines a to b of n; continue with offset b+1]` when lines remain, grep groups matches under a path line and ends with `[n more matches in m files; ...]`, glob ends with `[k more files not shown; ...]`; a result over its budget ends with the `[full output: ...]` note (D37). `view::tool_detail` also reads the older outputs.
